\begin{chineseabstract}
随着虚拟现实、人工智能等数字技术的快速发展，人机交互正逐步从以键盘、鼠标为主的单一输入范式，转向融合多感知通道的沉浸式交互形态。然而，当前实体展览中的公共交互装置仍存在交互方式趋同、情感反馈缺失、体验深度不足等问题。本文针对上述问题，设计并实现了一套面向实体展览的沉浸式多模态交互系统。系统以Unity引擎为核心交互平台，整合了手势识别、面部情绪识别、交互应用状态感知等多源信息，并基于大语言模型智能体（Qwen3.5 + DeepAgent）构建中央决策模块，实现对虚拟场景与物理装置（LED灯阵、音效等）的协同控制。本文详细阐述了系统的总体架构、网络通信协议、智能体工具调用机制、关键视觉与交互模块的实现方法，并展示了实体装置的设计与集成。本系统为构建更具情感连接与沉浸感的公共展览交互体验提供了可行的技术路径与设计参考。

\chinesekeyword{多模态交互；游戏引擎；智能体；情感计算；实体展览}
\end{chineseabstract}

\begin{englishabstract}
With the rapid development of digital technologies such as virtual reality and artificial intelligence, human-computer interaction is gradually shifting from a single input paradigm dominated by keyboards and mice to an immersive interaction paradigm that integrates multiple sensory channels. However, current public interactive installations in physical exhibitions still suffer from homogenized interaction methods, lack of emotional feedback, and insufficient experience depth. To address these issues, this thesis designs and implements an immersive multimodal interaction system for physical exhibitions. The system uses Unity engine as the core interaction platform, integrating multi-source information such as gesture recognition, facial emotion recognition, and application state perception, and constructs a central decision-making module based on large language model agents (Qwen3.5 + DeepAgent) to achieve coordinated control of virtual scenes and physical devices (LED arrays, sound effects, etc.). This thesis elaborates on the system's overall architecture, network communication protocols, agent tool-calling mechanisms, implementation methods of key visual and interaction modules, and demonstrates the design and integration of physical devices. This system provides a feasible technical path and design reference for constructing more emotionally connected and immersive public exhibition interactive experiences.

\englishkeyword{Multimodal Interaction; Game Engine; Agent; Affective Computing; Physical Exhibition}
\end{englishabstract}

\section{研究背景和意义}

随着虚拟现实、人工智能等数字技术的快速发展，现代人机交互方式正逐步从以键盘、鼠标为主的单一输入范式，转向融合多感知通道的沉浸式交互形态。公共交互装置作为现代城市空间与博物展览中的新兴艺术表达媒介，致力于构建人与作品之间的深度对话\citing{wen2022huadong}，而上述技术进步为其体验深度与表现形式拓展了新的可能。

从当今的实体展览的现状来看，实体展览逐渐从藏品陈列和静态信息呈现的展示模式，向强调观众参与和体验感受的方向演进。博物馆等机构持续致力于优化其与观众的互动方式，特别是在观众与文物、艺术品等展品的交互层面，当代博物馆与艺术展厅致力于打破“请勿触摸”的传统禁锢，转而追求更具实践性、叙事性与沉浸感的互动体验\citing{ogrizek2024vr}\citing{jiang2024dunhuang}。

然而，当前展览中的公共交互装置在交互体验上仍存在明显不足。一方面，部分系统仅简单引入数字屏幕与触控交互，参观者的体验与操作普通电子设备无异，未能充分发挥实体展览特有的现场感与空间优势。另一方面，由于设计范式趋同，许多装置的交互方式、反馈逻辑与视觉表现呈现同质化倾向，难以有效促进参与者的情感投入与持续探索，导致可互动但不耐体验的现象。这使得互动装置未能充分实现其作为展览媒介应有的情感沟通与意义建构价值，观众与作品之间难以建立稳定而深入的联系。

针对上述问题，本课题引入游戏引擎技术作为核心开发平台。Unity 等现代游戏引擎凭
借其卓越的实时渲染、场景管理与高效图形渲染能力，使得高性能、高复杂度的三维空间表
现和实时反馈成为可能，这为交互式视觉内容的构建提供了绝佳的平台支持。通过借鉴成熟
的电子游戏交互机制与空间叙事方法，可以有效反哺现实展览系统，增强其趣味性与深度\citing{kruger2024gameengines}。

在多模态情感识别技术方面，随着深度学习在计算机视觉与运动捕捉领域的广泛应用，系统能够精准捕捉用户的身体姿态、手势及面部表情。与此同时，人类对计算机情感理解与交互的需求愈加广泛\citing{tao2024multimodal}。相较于传统控制器，这种具身化的交互方式能更自然地映射用户的心理状态，从而实现更高维度的情感化沉浸体验。

在智能体技术层面，随着大语言模型（LLM）与视觉语言模型（VLM）的迅速发展，基于基础模型的智能体已成为人工智能领域的重要研究方向。智能体被定义为一类交互系统，能够感知视觉刺激、语言输入及其他环境数据，并产生有意义的具身化动作\citing{durante2024agent}。在展览交互场景中，智能体可以充当感知层与执行层之间的决策中枢：根据多模态感知输入理解用户意图，结合任务规划与常识推理生成控制指令，并通过工具调用实现对虚拟场景与物理设备的协同控制。这种“感知—决策—执行”的闭环架构为构建更具智能性的沉浸式交互系统提供了技术基础。

在此背景下，围绕实体展览场景，开展多模态沉浸式交互系统的设计研究，对于重构用户体验、创新情感反馈机制、探索技术融合应用具有重要的现实意义。

\section{实体展览交互装置研究进展}

现有研究指出，一套完整的博物馆交互展览系统通常包含数据层、逻辑层与展示层三层架构。其中，展示层负责提供高保真的三维渲染与多模态交互界面，支持用户在实体空间中以多样方式与虚拟内容互动\citing{li2024exhibition}。本课题的设计与实现聚焦于展示层的构建与优化。

互动装置艺术作为连接展览内容与观众的关键媒介，其价值不仅在于满足基础的视听需求，更在于营造用户在参与过程中生理、心理乃至精神层面的综合情感体验。温文龙等学者基于互动仪式链理论指出\citing{wen2022huadong}，通过预设具有规范性、表演性与趣味性的互动仪式，可以为参与者创造特定的体验情境。如图\ref{fig:ritual}所示，在仪式化的互动过程中，情感能量得以产生、分享与传递，并通过“仪式链”的连续性维持高强度的参与体验，这为互动装置的情感化设计提供了理论依据\citing{wen2022huadong}。

情感化设计是一种将人的情感需求放在首位的设计方式\citing{norman2005emotional}。相关研究从实验验证与设计应用层面证实了情感化设计在提升用户参与度和满意度方面的重要性。例如，在面向特殊人群的媒体设计中，基于感官代偿理论的多模态交互已取得成熟应用。李静雅等人通过 TouchDesigner 软件实验，提出了节奏与视觉形态关联的音乐可视化模型：圆形—慢节奏、方形—中节奏、三角形—快节奏\citing{li2023music}，这为视听联觉反馈设计提供了参考，也为本课题的交互作品《回声之境》的视觉生成逻辑提供了实证依据。Valérian Fraisse 等人通过对大量文献的系统性综述，提出了一个从艺术意图、交互设计与系统设计三个视角描述交互式声音装置的概念框架，并构建了一个涵盖多维度特征的可视化数据库，揭示了该领域的研究趋势与实践多样性\citing{fraisse2021sound}，为本课题的系统性设计提供了方法论参照。本课题旨在将这一思路延伸至通用展览场景，通过多模态交互强化装置的情感沟通与意义建构能力，从而在观众与作品之间建立更稳固的深层连接。

此外，交互装置的核心技术基础在于其输入设备与交互方式。研究表明，在博物馆的虚拟现实交互中，为机械结构复杂的交互任务提供实体工具，能对用户体验产生积极影响\citing{ogrizek2024vr}。如图~\ref{fig:liangzhu-interactive} 是位于浙江省杭州市余杭区良渚博物馆内的一处交互装置，其允许参观者通过操作实体装置与虚拟场景互动，很好地体现了这种虚实联动的交互理念。这一发现支撑了本课题实体装置与虚拟反馈结合的设计路线——在本课题展览装置设计中，将向参观者提供与交互应用内部场景相呼应的 3D 打印物件作为输入工具。

\section{多模态交互与智能体技术研究进展}

多模态交互是一种变革性的人机交互方法，允许用户通过语音、手势、触控、注视和触觉等多种输入与输出模态与系统进行交互。随着传感器技术和机器学习的进步，多模态系统在虚拟助手、智能环境、医疗保健和辅助技术等各类应用中日益重要\citing{tao2024multimodal}\citing{matsanusi2024milsdem}。从系统架构的角度看，多模态交互涉及三个关键层次：模态层面涵盖视觉、听觉、触觉等多种感官形式；技术层面包括手势识别、语音识别、运动传感、虚拟现实等软硬件解决方案；学习与干预层面则关注如何通过系统设计支持用户的认知、情感与技能发展\citing{matsanusi2024milsdem}。

\subsection{情感识别与大模型赋能的多模态感知}

近年来，大模型技术的迅速发展为情感识别提供了全新的研究范式。如图\ref{fig:emotion-lm}所示，吴敖等人的《情感识别大模型研究综述》将多模态情感识别分为统一编码、层次化融合和生成式模型三种架构\citing{matsanusi2024milsdem}。统一编码架构将不同模态或任务的异构数据映射到统一的语义表示空间中，具有很高的挑战性——例如张艺媛等人提出的Meta-Transformer能将多达12种模态统一映射到参数冻结的Transformer编码器，显著减少了新模态的对齐参数量，实现广泛模态兼容性。

\begin{figure}[htbp]
  \centering
  \includegraphics[width=0.6\textwidth]{pic/截屏2026-01-09 18.51.42.png}
  \caption{情感识别大模型分析维度}
  \label{fig:emotion-lm}
\end{figure}

在视觉情感识别领域，面部表情作为最直接的视觉情感表达载体，能够精确反映个体的情绪状态，近期的学术研究包括分层窗口机制、预训练ViT、双流协作机制等。然而，高精度面部解码存在明显局限性，在面对遮挡、低分辨率或复杂情感时，其分析能力会显著下降；当面部信息不明确时，肢体动作便成为解读情感强度与行为意图的关键线索。

对于本课题的具体需求，由于按钮序列、虚拟空间内事件信息较为简单，可直接使用固定算法处理，因此可以单独针对视觉信息使用单模态情感识别模型进行融合计算，在计算开销与识别准确率之间取得平衡。本课题中，面部表情和肢体动作的视觉识别均采用成熟的工业级方案MediaPipe，以快速搭建可用环境并方便集成于展览系统。

\subsection{目标导向交互与状态追踪框架}

在交互系统设计中，如何平衡参展者自主性与叙事连贯性一直是核心挑战。传统基于选项的对话系统将参展者选择限制在预设菜单中，虽然确保了叙事的可控性，但严重削弱了参展者的能动性（agency）。近年来，随着大语言模型技术的发展，研究者开始探索如何利用LLM的灵活性提升交互系统的自主性，同时通过结构化框架保持设计的可控性。

目标导向交互（Goal-Oriented Interaction）将交互构建为状态驱动的图结构谜题：节点表示关键目标（里程碑），边表示合法的状态转移。设计者通过定义状态转换条件来控制交互进程，同时允许参展者在达成目标的过程中进行自由形式的选择。这种框架既提供了结构化的叙事引导，又保留了参展者创造解决方案的空间。

状态追踪（State Tracking）是目标导向交互中的关键技术。传统对话状态追踪（DST）技术主要适用于结构化任务导向型对话，通过解析用户话语更新槽位值。然而，在开放式的交互应用场景中，状态追踪需要处理更复杂的叙事发展和战略交互。近期研究提出使用问答型大语言模型（QALM）结合对话历史分析来实现状态追踪，通过评估自然语言问题来判断目标达成情况，从而驱动状态转换。双LLM架构是目标导向交互系统的典型实现方案：对话语言模型（DLM）负责生成角色对话，保持交互的自然性和灵活性；问答语言模型（QALM）则负责状态追踪和决策，确保交互进程符合设计者意图。这种解耦设计既利用了LLM的生成能力，又通过监督结构弥补了其在长期连贯性方面的不足。

在实体展览场景中，目标导向交互框架具有重要应用价值。通过将展览体验构建为目标导向的交互流程，系统可以在保持整体叙事连贯性的前提下，支持参展者的自主探索和创造性参与。状态追踪技术则可用于监控参展者的情绪状态、交互进度和认知负荷，实现自适应的反馈调整。

\subsection{智能体作为多模态交互的决策中枢}

智能体（Agent）作为人工智能领域的重要研究方向，近年来随着大语言模型与视觉语言模型的迅速发展而受到广泛关注。智能体被定义为一类交互系统，能够感知视觉刺激、语言输入及其他环境数据，并产生有意义的具身化动作\citing{durante2024agent}。这种定义强调了智能体与环境之间的紧密耦合关系——智能体不仅被动接收信息，更重要的是能够主动对环境施加影响。

在智能体的核心架构方面，学者们提出了包含五个主要模块的智能体变换器框架（Agent Transformer Framework）：环境感知与任务规划模块负责解析多模态输入并分解任务目标；智能体学习模块支持从数据或反馈中优化行为策略；记忆模块用于存储上下文与历史交互信息；动作预测模块生成具体的执行指令；认知模块则负责高级推理与常识理解\citing{durante2024agent}。这一框架为智能体系统的设计与实现提供了清晰的结构化指导。

当前智能体系统越来越多地集成大语言模型或视觉语言模型来增强感知与决策能力。大语言模型可被扩展为各环境中的智能体，当与领域特定知识模块结合时，能够执行复杂的动作和任务\citing{durante2024agent}。同时，工具使用与知识库查询能力的整合已成为智能体推理过程中的重要方向，智能体通过利用来自多种来源的结构化和非结构化数据，能够增强对复杂情境的理解并提供更准确的响应。

在智能体的学习方法方面，上下文学习（In-context Learning）作为大语言模型时代的新兴方法，在解决自然语言处理任务方面展现出有效性，少样本提示成为跨任务泛化模型输出的有效方式\citing{durante2024agent}。对于面向展览场景的交互系统而言，上下文学习是最为适用的方法——通过精心设计的提示词（Prompt）即可实现不同展览场景的任务适配，而无需大规模重新训练或收集专家演示数据。

多模态理解是创建通用智能体面临的重要挑战。由于缺乏包含视觉、语言和智能体行为的大规模数据集，当前的跨模态理解策略仍需进一步改进\citing{durante2024agent}。一种可能的解决思路是使用"冻结"的大语言模型与视觉编码器的组合架构。一种在当前技术条件下的合理折中方案是采用感知-决策解耦的架构设计——前端多模态感知模块负责手势、面部情绪与环境状态的识别，决策端由视觉语言模型（Qwen3.5）承担推理任务。这种感知与决策的解耦在保证系统实时性的同时，也便于各模块的独立优化与迭代升级。

综上所述，智能体技术为沉浸式多模态交互系统的构建提供了"感知—决策—执行"闭环的决策中枢。在展览场景中，多模态感知模块负责捕捉参展者的手势、表情及环境状态，目标导向交互框架负责维护叙事结构与状态转换规则，而智能体则作为整合感知输入与决策输出的核心控制器。本课题《回声之境》系统在架构设计上正是借鉴了这一思路：通过MediaPipe实现多模态感知输入，采用DeepAgent框架结合Qwen3.5大语言模型作为决策中枢，将展览体验分解为多个情感状态节点（如迷茫、探索、共鸣、自由），基于状态转换规则生成相应的视觉、听觉和物理反馈。这种设计既保持了情感叙事的连贯性，又为参展者提供了丰富的交互可能性。

\chapter{《回声之境》系统总体设计}

\section{设计理念与叙事驱动}

本系统面向实体展览场景，旨在构建一套沉浸式多模态交互系统。主要需求包括：

\begin{enumerate}
\item \textbf{多模态感知能力}：能够实时捕捉用户的手势、面部情绪，并同步交互应用内部状态。
\item \textbf{智能决策能力}：基于多源信息，实现情感驱动的动态反馈决策。
\item \textbf{虚实融合执行能力}：能够同时控制虚拟场景中的视觉、音效表现，以及实体空间中的灯光等物理装置。
\item \textbf{模块化与可扩展性}：各模块松耦合，便于独立开发、调试与后续扩展。
\item \textbf{实时性与稳定性}：满足展览场景下的低延迟响应与长时间稳定运行要求。
\end{enumerate}


恰如未来人们与虚拟世界的交互方式将超越传统的键盘鼠标输入，本项目探索一种由人工智能驱动的、富有趣味性的新型展览交互方式。结合实体的按钮装置和参展者情绪，在交互应用中做出相应的图形图像变化，并以此作为核心交互手段设计类游戏化关卡。

交互应用《回声之境》遵循情感化设计理念，交互设计以情绪变化为导向。以下为核心设计要点：

\subsection{场景情绪基调}

《回声之境》交互应用具有叙事性质，伴随着参展者情绪变化和交互应用节奏的推进，在不同阶段设计了不同情绪基调的场景。在每个场景内，旅人的音符音色和音阶会适应场景而变化，力求营造富有诗意的参观体验。


\subsection{叙事结构与手法}

《回声之境》的故事隐喻了作者步入大学以来的心路历程。作品通过旅人的旅程，探讨自我认知、成长与未来召唤的主题。

应用设置三个章节，分别为初域·未定之原、聚落群·彼方的光影之城、深流之径·未被触及的知识海。

\subsection{旅人人物形象设计}

\textbf{「那位没有过去，却正被未来召唤的人」}

没有人知道旅人从何而来。当他睁开眼时，正立于“未定之原”的浅雾中，风声像未完成的句子，光像正在犹豫的记忆。

他没有名字，不是因为遗忘，而是因为他从未真正拥有过。旅人不是被放逐，也不是被召唤。他之所以存在，是因为回声之境“正在形成”，而只有那些\textbf{心中仍在寻找自我形状的人}，才会在世界未成形之时走进它。

在他胸口，有一块微弱跳动的光核——不是心脏，而是\textbf{他尚未理解的自己}。随着他前行，光会改变颜色、节奏与温度，它既是力量，又是负担；既是答案，又是疑问本身。旅人来到这里，是因为他已走到人生某个模糊的分叉：不再属于过去，却尚未准备好面对未来。回声之境正是这种状态的具象化。因此，旅人不是外来的闯入者，而是\textbf{这个世界尚未成形部分的化身}。

\section{交互机制与状态设计}

\subsection{音乐交互设计}

\subsection{交互场景与关卡设计}

基于故事流程中的三个核心章节，本系统设计了完整的交互场景与关卡流程，确保情感叙事与交互机制的深度结合。三章分别对应”迷茫-锚定”、”碰撞-边界”、”敬畏-自由”三组情感状态的转换，各章节的交互目标与视觉意象形成一一对应的映射关系。

\subsubsection*{第一章：初域·未定之原——自我迷茫与锚定}

本章对应情感状态从”迷茫”到”锚定”的转换，核心目标是解锁水滴音符，使参展者学会在未定中锚定自我。设计理念借鉴《最后的篝火》的温柔引导机制，全程无惩罚，通过渐进式教学让参展者理解”我的声音可以塑造世界”的核心逻辑。

本章开场场景中的远景山峦承担着视觉引导与情感暗示的双重职责。半透明、边缘模糊的山峦形态隐喻着旅人尚未明晰的方向感——山峦的不稳定抖动象征着旅人内心的徘徊与探寻；当山峦被音符固化后逐渐变得坚实，则对应着旅人在迷茫中逐步锚定自我、找到方向的过程。视觉层面的虚实转换与情感层面的迷茫-锚定转变形成对照，使参展者在潜意识层面感受情绪叙事的递进。

关卡流程设计为四个阶段：参展者首先从迷雾中显现，面对半透明流动的山峦和旷野，在旁白引导下尝试与世界互动；随后在引导下按下水滴音符，山峦短暂抖动后恢复流动，仅留下水波纹光痕，参展者需持续奏响音符才能固化山体；进而进入三个方向锚点谜题——落定的石阶（过去的锚点）中需观察漂浮石块的流动规律，在合适时机奏响音符将其固化形成连续跳台；无风的山谷（当下的锚点）中需依次固化4个乱流核心，每固化一个核心，乱流减弱一分，地面起伏变小；迷雾的边界（未来的锚点）中参展者需自主判断何处应固化成山体、何处应铺成台阶，独立开辟道路；最终三个锚点全部激活后，迷雾散去，未定之原固化为稳定地貌，一条宽阔光路延伸向光影之城。

本章多模态交互设计涵盖四个维度：持续捏合手势对应持续奏响音符；发声音量对应固化范围，声音越大单次固化区域越广；山体从半透明流动态逐渐固化为坚实青青山体；水滴音符从单音变为完整短句，风声逐渐柔和。

\subsubsection*{第二章：聚落群·彼方的光影之城——关系探索与边界}

本章对应情感状态从”碰撞”到”边界”的转换，核心目标是解锁道路交错音符，使参展者学会在关系中保持自我边界。设计理念参考《最后的篝火》”中心枢纽+多分支NPC故事线”结构，每个分支对应一段社交与情感的隐喻。

旅人进入城市时，人声嘈杂导致街道挤压变窄，尝试用水滴音符无效，系统由此明确告知需要新规则。关卡设置四个分支区域：回声交汇所（相遇与连接）中，参展者帮助影子旅者连接断裂的光路，通过动作同步建立共鸣，再用水滴音符连接彼此道路；情绪风塔（共鸣与分寸）中，参展者逐层应对欢喜、悲伤、愤怒、恐惧四种情绪，学会既共情又不被吞噬；镜影回廊（他人评价与自我认知）中，参展者在布满镜面的回廊里忽略外界评价，锚定真实的自我；离别的岔路口（相遇与放下）中，参展者帮助影子旅者明白离别不是结束，各自走向自己的方向。集齐四个碎片后，城市建筑停止挤压变形，旅人脚下的路始终保持宽阔平稳。

本章核心交互机制包括：情绪折射——建筑随旅人情绪强度变化，情绪平静时建筑舒展，情绪波动时建筑扭曲；共鸣系统——与影子旅者动作同步达到80\%以上触发共鸣效果；边界保护——道路交错音符可划定自我边界，使参展者不受他人情绪影响。

\subsubsection*{第三章：深流之径·未被触及的知识海——知识接纳与自由}

本章对应情感状态从”敬畏”到”驾驭”再到”自由”的转换，核心目标是解锁海浪音符和风音符，使参展者获得完全的表达自由。设计理念体现”学得越多，未知越多”的核心命题，通过知识潮机制实现渐进式难度提升。

关卡分为浅滩区与深潮区两个阶段。浅滩区设置知识潮机制：参展者每获取一个知识碎片（对应观察、耐心、试错、联结、放下、接纳六个学习特质），潮水上涨，露出的礁石减少，但深渊光点变多更亮；集齐六个碎片后解锁海浪音符，参展者学会在知识的潮水中保持稳定。深潮区设置三道情感浪潮，分别对应迷茫、遗憾、无知三种成长困境，旅人需用已解锁的音符逐一化解；触碰海心之核后，四个音符旋律合为一首完整曲子，风音符由此解锁，参展者获得完全的表达自由。值得说明的是，开篇的晴天娃娃在深潮区回归，旅人由此明白它从未抛下自己，只是在前方等待——该设计实现叙事层面的伏笔回收。

完成深潮区挑战后，系统进入自由探索阶段，参展者可自由奏响四个音符，每个音符都会改变整个世界形态，实现无限探索可能。该阶段设计使参展者充分体验”学以致用”的成就感与”随心所欲不逾矩”的自由状态。

三章的叙事线索层层递进：第一章聚焦自我认知，未定之原是对自我迷茫的具象化；第二张聚焦关系探索，光影之城是对人际边界的具象化；第三章聚焦世界接纳，深流之径是对知识与未知态度的具象化。四个音符作为定形自我、连接他人、接纳未知、去往未来的能力象征，共同构成了旅人从迷茫走向自由的完整成长弧线。

\subsubsection*{状态图设计与情感里程碑}

系统将《回声之境》的展览体验建模为一个三层递进的状态图，对应故事中的三个核心章节和四个音符的解锁过程。状态图包含三个主要章节状态和四个音符解锁子状态，形成完整的成长路径：

\begin{itemize}

状态追踪模块负责监控观众进度并管理状态转换。与传统的对话状态追踪不同，本系统的状态追踪需要处理更复杂的多模态输入和情感语义。系统采用基于规则的启发式方法与机器学习相结合的方式实现状态追踪：

\begin{enumerate}
    \item \textbf{多模态特征提取}：从手势识别、面部情绪识别和交互应用状态同步模块提取关键特征，包括手势类型、情绪强度、交互频率等
    \item \textbf{状态概率计算}：使用加权融合算法计算观众处于各个状态的概率，权重根据特征重要性动态调整
    \item \textbf{转换条件评估}：评估状态转换条件是否满足，包括时间阈值、交互次数阈值和情感变化趋势
    \item \textbf{状态确认与转换}：当转换条件持续满足一定时间后，确认状态转换并更新系统状态
\end{enumerate}

\subsubsection*{决策生成与反馈协调}

决策模块基于当前状态和感知输入生成协调的反馈策略。系统采用分层决策机制：

\begin{itemize}
    \item \textbf{底层反应}：对即时交互（如手势识别）生成快速反馈，延迟控制在100ms以内
    \item \textbf{中层策略}：基于当前状态和短期交互历史生成策略性反馈，如调整音乐节奏或灯光模式
    \item \textbf{高层叙事}：管理长期的情感叙事发展，控制状态转换和章节推进
\end{itemize}

反馈协调机制确保虚拟场景、音频系统和物理装置的输出在时序和语义上保持一致。例如，当系统检测到观众情绪转为积极时，会同时调整虚拟场景的色调（暖色化）、音乐节奏（加快）和实体灯光（亮度提升），形成协调的多感官反馈。

\subsubsection*{自适应性与个性化}

系统支持一定程度的自适应调整和个性化体验。基于观众的交互模式和情绪反应，系统可以微调状态转换阈值和反馈强度。例如，对于交互频率较低的观众，系统会降低状态转换的时间要求，提供更积极的引导反馈；对于情绪反应强烈的观众，系统会调整反馈的强度，避免过度刺激。

这种目标导向交互框架使《回声之境》系统能够在保持整体情感叙事连贯性的前提下，支持观众的自主探索和创造性表达，实现了结构化引导与自由交互的平衡。

\subsection*{实体装置}

\section{智能体EchoAgent实现}

作为为《回声之境》服务的智能体，本文将其命名为 EchoAgent。EchoAgent 内部基于大语言模型构建，作为整个系统的决策层和中枢节点。TCP Socket 服务器与 EchoAgent 之间通过一个异步消息队列进行通信：服务器负责接收来自各类客户端（Unity、MediaPipe、Raspberry Pi 等）的消息，并将它们投入共享的消息队列；EchoAgent 则定时从队列中批量取出消息，经大语言模型理解后，自主决策并调用相应工具完成响应。

在系统启动流程上，本设计先创建全局消息队列，再创建 TCP 服务器并注入该队列的引用，最后创建 EchoAgent 实例，使其同时持有队列与服务器的引用。这种顺序确保了各组件在初始化时能够正确建立关联。

由于智能体需要主动向各个已连接的客户端发送消息或命令，本系统将这类操作封装为可被大语言模型调用的工具（Tools）。这里存在一个设计上的矛盾：工具的参数必须是字符串或数字等简单类型，以便大语言模型生成，然而向客户端发消息这一操作本质上需要持有 TCP 服务器实例的引用。为解决这一矛盾，本系统利用面向对象的闭包特性，在 EchoAgent 初始化时将 TCP 服务器实例保存为其成员属性，而工具函数则作为内部方法定义，通过隐式绑定到 \texttt{self} 来访问服务器实例，从而在不破环工具参数类型约束的前提下实现了对服务器的控制。

整个系统运行时，TCP 服务器与 EchoAgent 各自在独立的无限循环中运作：TCP 服务器持续监听端口、接收并解析来自客户端的消息，同时暴露发送消息的接口供外部调用；EchoAgent 则按固定时间间隔（默认五秒）批量取出消息队列中积压的所有消息，交由大语言模型进行理解与推理，再由模型自主选择并调用合适的工具完成响应。

\subsection{DeepAgent}

本系统采用 \textbf{DeepAgent} 框架，基座模型采用 \textbf{Qwen3.5-Plus}。DeepAgent是一个基于LangGraph和LangChain构建的智能体框架，具备深度的规划能力、高效的上下文管理及灵活的子代理委派机制，可通过\texttt{write\_todos}工具自动拆解复杂任务并动态调整执行计划；自动记忆压缩有效解决超长任务带来的上下文溢出问题；支持通过\texttt{task}工具实时创建子代理，在实现复杂功能的同时保持主代理上下文的简洁高效；无缝对接LangGraph的状态管理与LangSmith的监控、评估与部署能力。

\subsection{技能（SKILL）设计}

在大语言模型智能体的实际部署中，如何让模型有效理解任务环境并执行相应操作，是一个核心问题。传统的方案通常依赖提示词工程（Prompt Engineering），通过自然语言描述向智能体传递系统知识。然而，这种方式存在显著局限：提示词长度受限、描述易产生歧义、模型对结构化信息的理解效率远高于自由文本。

基于上述考量，本系统设计了一套专用的技能，通过结构化的机器可读格式向智能体传递系统知识，使智能体能够准确掌握交互系统的架构细节、通信协议、感知能力与可控设备。

\textbf{（1）系统架构描述模型}

 SKILL体系首先定义了系统的层次化架构模型。本系统采用“感知层—决策层—执行层”的三层星型拓扑结构，其中感知层包含手势识别、面部情绪识别与交互应用状态同步三个独立模块，各模块均以TCP Client方式向决策层上报数据；决策层以Qwen3.5 VLM为基座模型，结合DeepAgent框架实现Tool Calling能力；执行层则由Unity客户端与树莓派物理装置组成。SKILL中通过结构化字段明确各层的职责边界与数据流向，使智能体能够理解其在系统中的定位与作用。

\textbf{（2）标准化通信协议抽象}

智能体与各模块间的通信遵循标准化的JSON-over-TCP协议。SKILL对协议格式进行了形式化描述，包括消息类型体系（text、image、command、register四种消息类型）、客户端身份标识（echoagent、unity、mediapipe、raspberry\_pi）、以及请求追踪机制（request\_id字段用于关联请求与响应）。这种形式化描述使得智能体能够精确理解每条消息的语义，而非依赖自然语言的模糊表述。

\textbf{（3）感知事件模型}

感知层各模块上报的事件是智能体决策的主要输入来源。SKILL定义了一套统一的事件模型：每个事件包含来源标识（source）、事件名称（event）、事件数据（data，含位置坐标、置信度等）以及时间戳（timestamp\_ms）。在此基础上，SKILL进一步描述了各感知模块的具体事件类型与触发条件。

对于手势识别模块，定义了手部出现/消失、捏合（pinch）、捏合释放、双手张开、左右滑动手势等事件，并说明了捏合检测的算法原理——通过计算拇指尖（landmark 4）与食指尖（landmark 8）的欧氏距离实现，阈值设为0.06。对于面部识别模块，则定义了面部出现/消失事件，以鼻尖位置作为参考点。通过这种结构化描述，智能体能够准确判断当前收到的感知数据代表何种交互状态。

\textbf{（4）工具函数接口规范}

Tool Calling是智能体控制外部设备的唯一途径。SKILL定义了六个核心工具函数，每个函数包含功能描述、参数列表与返回值约定。工具函数的设计遵循“单一职责”原则：\texttt{control\_lights}负责灯光控制（颜色、亮度、模式三个参数）；\texttt{send\_to\_client}负责向指定客户端转发消息；\texttt{advance\_application\_chapter}与\texttt{trigger\_application\_event}分别用于交互应用叙事控制；\texttt{play\_music}与\texttt{set\_environment}则分别控制音频与视觉环境。参数类型均采用简单字符串或数值，避免复杂嵌套结构，降低VLM解析出错概率。

\textbf{（5）上下文感知与交互策略}

单纯的实时响应不足以构建连贯的交互体验，智能体还需理解交互应用叙事上下文与用户情感趋势。SKILL定义了上下文记忆的管理规范：智能体应维护最近五轮交互历史、当前交互应用章节与场景信息、参展者已获音符列表、以及情绪变化趋势。这些信息共同构成了决策的上下文基础。

在交互策略层面，SKILL定义了触发—响应的映射规则。当检测到手势捏合时，智能体根据当前场景决定触发音符演奏或场景交互；当情绪检测为正向时，灯光采用暖色调并提升亮度，音乐节奏加快；当情绪检测为负向时，则采用冷色调并降低亮度。这种规则化的策略描述使得智能体的决策行为具有可预测性与可解释性。

\textbf{（6）系统约束边界}

为防止智能体产生异常行为，SKILL还定义了系统级的约束边界，包括实时性要求（手势响应延迟低于100ms、灯光控制延迟低于200ms）、技术部署约束（仅支持局域网环境）以及内容安全限制（四个音符须按序获得、情绪反馈须柔和避免强刺激）。这些约束作为智能体决策的边界条件，确保系统在可控范围内运行。

\section{TCP通信与并发控制实现}

在分布式多模态交互系统中，各模块间的通信效率与可靠性直接影响系统的实时响应能力与用户体验。本节详细阐述系统网络通信的整体架构、协议设计演进过程以及关键实现机制。

\subsection*{通信架构概述}

系统采用TCP/IP协议实现模块间通信。决策模块（智能体服务端）与TCP Server一体化部署，作为通信中枢接收来自各感知模块的数据上报，并将决策指令下发至执行模块。Unity客户端、MediaPipe客户端、树莓派客户端等感知与执行模块均作为TCP客户端连接至决策中枢。这种星型拓扑结构实现了各模块的松耦合设计：各感知模块仅需关注自身数据采集，无需了解其他模块的存在；决策模块则充当统一的信息汇聚与分发中心，负责协调各模块间的数据流转。

在通信协议的选择上，本系统经过深入比较，最终确定采用TCP Socket而非WebSocket作为传输层协议。TCP Socket相比WebSocket具有更低的协议开销和传输延迟，且能够提供更精细的流量控制与连接管理能力。此外，TCP Socket支持更底层的网络配置选项，便于针对展览场景的特定需求进行优化调参。

\subsection*{协议设计演进}

在协议格式的设计过程中，本系统经历了从二进制协议到JSON文本协议的演进历程。

\textbf{（1）二进制协议方案}

早期设计采用长度前缀+消息类型的二进制协议格式，具体结构为：4字节大端序无符号整数表示载荷长度，1字节无符号整数表示消息类型（\texttt{0x00=TEXT}、\texttt{0x01=IMAGE}、\texttt{0x02=COMMAND}、\texttt{0x03=REGISTER}），其后为载荷数据。这种二进制协议在理论上具有最高的解析效率，但在实际开发中暴露出若干问题：由于图片数据与文本数据采用完全不同的编码方式，智能体在处理混合类型消息时需要额外的类型判断与解码逻辑，增加了中间件的开发复杂度；此外，二进制协议的调试与维护也较为困难，难以在开发阶段进行直观的协议检查。

\textbf{（2）JSON文本协议方案}

基于上述实践经验，本系统最终采用长度前缀+UTF-8编码的JSON协议格式。该协议将所有数据统一封装为JSON对象，包含以下四个核心字段：

\begin{itemize}
\item \texttt{type}：消息类型，取值为 \texttt{text}（普通文本消息）、\texttt{image}（Base64编码的图片数据）、\texttt{command}（控制命令）、\texttt{register}（客户端注册）
\item \texttt{data}：载荷内容，文本消息时为UTF-8字符串，图片消息时为Base64编码的二进制数据
\item \texttt{client\_type}：发送者身份标识，取值包括 \texttt{echoagent}（智能体）、\texttt{unity}（Unity客户端）、\texttt{mediapipe}（感知模块）、\texttt{raspberry\_pi}（树莓派控制端）
\item \texttt{request\_id}：请求追踪标识，采用UUID格式，用于关联请求与响应
\end{itemize}

该协议格式具有以下优势：JSON的文本形式便于开发阶段的调试与日志分析；统一的数据封装方式简化了智能体端的协议解析逻辑；Base64编码虽然增加了约33\%的数据体积，但换取了协议的一致性与可维护性。考虑到本系统运行于本机与局域网环境下，网络带宽充足且延迟极低（通常低于5ms），上述开销在实际使用中完全可以接受。

\subsection*{Unity客户端的线程安全发送机制}

Unity引擎基于单线程执行模型，其生命周期方法（如 \texttt{Update}、\texttt{FixedUpdate}等）均在主线程中运行。然而，TCP网络通信涉及I/O操作，为避免阻塞主线程导致帧率下降，本系统在 \texttt{AgentCommunicator} 组件中采用了异步发送机制，并通过信号量（Semaphore）实现线程安全的发送控制。

具体实现上，\texttt{SendRawAsync} 方法采用 \texttt{SemaphoreSlim} 作为发送锁，确保在同一时刻仅有一个发送任务持有网络流的使用权。当多个协程或异步任务同时发起发送请求时，发送锁保证这些请求被串化执行，避免TCP粘包或数据交错问题。锁的获取与释放位于 \texttt{try-finally} 块中，确保即使在网络异常情况下也能正确释放资源，防止死锁发生。

此外，\texttt{AgentCommunicator} 通过 \texttt{SynchronizationContext} 将接收到的网络消息投递回Unity主线程执行回调，从而在不影响应用帧率的前提下完成消息的解析与分发。这种设计在保持网络通信高效性的同时，确保了所有应用逻辑均在主线程中执行，符合Unity的线程安全要求。

旅人的行走、演奏等动画通过Unity的Animator组件与状态机实现，

\subsection{音符UI动效}

\textbf{使用DOTween实现UI动效}：DOTween是Unity引擎中一款轻量级的补间动画插件，其核心机制是将任意数值属性在起始值与结束值之间按预设的缓动曲线进行插值运算，生成平滑的过渡动画。在《回声之境》的MusicNote组件中，DOTween被用于实现音符获取与演奏两类核心交互动效。获取音符时，系统根据类型分支执行差异化的时序编排；演奏音符时，利用\texttt{DOTween.Sequence()}组合颜色过渡与发光脉冲循环，实现具有节奏感的演奏反馈。

\subsection{轨道摄像机}

\textbf{Cinemachine}是Unity引擎中一套功能完备的程序化相机控制模块。其核心设计理念在于将相机的行为抽象层与实际物理相机相分离，实现高度灵活且可组合的镜头系统。在本课题中，Cinemachine主要用于实现旅人跟随功能，使画面表现更具叙事性和电影感。

具体实现上，首先在场景中设置一个基准Camera，并为其挂载\textbf{Cinemachine Brain}组件，该组件负责管理虚拟相机之间的切换。随后创建\textbf{Cinemachine Camera}实体，并对其Procedural Components进行配置：\textbf{Position Control}设为\textbf{Spline Dolly}模式，使相机能够沿预设路径移动；\textbf{Rotation Control}设为\textbf{Rotation Composer}模式，用于动态调整相机旋转角度以保持对目标的追踪；\textbf{Noise}采用\textbf{Basic Multi Channel Perlin}配置，为相机轨迹添加可控的微震动效果，增强画面层次感与真实度。

进一步地，在场景中构建一条\textbf{Spline（样条曲线）}路径，并将Cinemachine Camera的Spline Dolly组件与该样条曲线绑定，约束相机的移动范围。设置\textbf{Automatic Dolly}功能，选择\textbf{Nearest Point To Target}跟随策略，使相机自动定位至样条曲线上距追踪目标最近的点位。综合上述配置，相较于传统直接跟随模式，基于样条曲线的轨道式跟随机制可实现更加平滑且富有叙事感的镜头运动，显著提升画面表现的电影化程度。

\subsection{风格化渲染}

在本课题的交互作品《回声之境》中，远景山峦与草地场景采用非真实感渲染（NPR）技术实现风格化的视觉表现，核心通过顶点着色器偏移与菲涅尔效应营造独特的画面氛围。

\begin{figure}[htbp]
  \centering
  \includegraphics{pic/Unity Shader入门精要 GPU渲染管线.png}
  \caption{《Unity Shader 入门精要》GPU渲染管线\citing{feng2016unityshader}}
  \label{fig:unity-shader}
\end{figure}

着色器（Shader）是运行在 GPU 上可编程的图形程序，分为顶点着色器（Vertex Shader）和片元着色器（Fragment Shader）\citing{feng2016unityshader}。如图~\ref{fig:unity-shader}，GPU 的渲染管线包括下面的工序：顶点着色器处理顶点的坐标转换信息，而片元着色器处理像素颜色数据计算信息。顶点着色程序从GPU 前端模块中获取到图元信息并执行顶点坐标的空间转换、 法向量的空间转换以及光照计算等操作，最终将计算的数据传输到指定的寄存器之中；随后片元着色程序从中提取所需要的数据，通常为纹理、坐标、光照信息等。并根据这些数据以及从应用程序传递而来的纹理信息执行每个片元的颜色计算，最后将处理后的数据信息传送至光栅操作模块。片元着色程序对每个片元进行独立的颜色计算，最终输出的值就是该片元最后呈现的颜色\citing{chen2024u3d}。

在Unity基于URP渲染管线中，可使用Cg或HLSL语言编写着色器，也可使用节点式的可视化编辑工具ShaderGraph。将风速、风强度、噪声纹理缩放、草地区域色彩值等设置为可实时调整的材质属性，以便后续结合多模态情感识别结果进行动态变化。下面以半透明抖动山峦和风格化草地为例说明着色器设置。

\textbf{（1）半透明抖动山峦着色器}

远景山峦在场景中承担着视觉引导与氛围渲染的职责，其半透明且边缘模糊的视觉效果通过菲涅尔效应与顶点随机偏移协同实现。

\textbf{菲涅尔材质}：采用Schlick近似公式计算菲涅尔因子：

$$F_{R} = F_{0} + (1 - F_{0}) \cdot (1 - \cos\theta)^{5}$$

其中 $F_{0}$ 为基础反射率，$\theta$ 为视线方向与表面法线的夹角。当 $\theta$ 增大时，菲涅尔因子趋近于1，使山峦边缘呈现明亮的发光效果；而接近正对视角的区域则保持较高的透明度，呈现出轮廓模糊、若隐若现的质感。该特性使山峦在深色背景下呈现出柔和而富有层次感的轮廓线。

\textbf{顶点着色器随机偏移}：山峦的抖动效果于顶点着色器中实现。通过引入基于时间的连续噪声函数，对各顶点进行随机的微小偏移，形成起伏不定的轮廓形态。

\textbf{Uniform参数控制}：为便于外部动态调控山峦的视觉表现，着色器预留了四个可调参数：

\begin{itemize}
\item \textbf{FresnelPower}（Float）：控制菲涅尔效应的衰减速率，较小取值使边缘发光范围扩展，较大取值则使发光收敛于更窄的边缘区域；
\item \textbf{FresnelColor}（Color）：定义边缘发光的颜色，可根据场景氛围进行调整；
\item \textbf{WobbleSpeed}（Float）：控制抖动动画的时间节奏，较快速度产生轻微颤动，较慢速度则呈现缓慢起伏；
\item \textbf{WobbleIntensity}（Float）：控制抖动的幅度大小，决定山峦轮廓的模糊程度。
\end{itemize}

上述参数通过C\#脚本直接引用材质对象进行动态修改。在Unity中，可通过 \texttt{GetComponent<Renderer>().material} 获取材质实例，并使用 \texttt{material.SetFloat()}、\texttt{material.SetColor()} 等方法实时调整参数值。该方式便于与智能体模块对接，智能体可通过标准化接口向渲染模块下发参数调整指令，实现山峦视觉表现随情绪氛围的动态变化。

\textbf{（2）草地动态效果}

草地场景的动态效果本质上是草丛几何体顶点的规律性偏移，需要在顶点着色器上操作。为模拟随风摆动的动态，最核心的工具是连续噪声函数，其数学目标是构造一个连续可导、局部相关、全局随机的函数 $N(x,y,z) \in [-1,1]$。相比真正的随机数，它满足偏导数 $\partial N / \partial x \neq 0$ 且变化平滑。如图\ref{fig:noise-2d}所示，这是一张满足上述要求的在二维空间上分布的噪声图像，将其灰度值线性映射到 $[-1,1]$ 区间即可表示风力大小。将噪声函数的位移值随时间移动采样，构建滚动纹理，即可作用于草丛的顶点偏移形成摆动效果。

\textbf{（3）性能优化}

草地场景中存在成千上万的渲染实体，如果不加任何优化，将会造成严重的图形 API 调
用开销。针对这个问题，剔除技术和 GPU Instancing 技术是两种有效的优化手段。

在三维图形渲染中，剔除技术是提升性能的重要手段之一。其中，视锥体剔除（Frustum Culling）作为一种基于空间可见性的剔除方法，其核心原理是去除位于摄像机视锥体范围之外的三维模型\citing{chen2024u3d}，从而避免对不可见物体进行后续渲染计算。通过实施视锥体剔除，可显著降低每一帧中需提交至渲染管线的几何体数量。这一方面减少了 CPU 需要处理的顶点数据量，另一方面也直接降低了 GPU 所需执行的顶点着色与片元着色负载，进而有效减轻overdraw 现象。与此同时，由于场景中实际提交渲染的物体数量减少， CPU 生成的 DrawCall数目也相应下降，有助于缓解图形 API 调用开销，提升绘制效率。

此外，为进一步优化渲染性能，还可结合 GPU Instancing 技术。该技术通过合并相同网格的多次绘制调用，能够进一步减少 DrawCall 数量，从而在 CPU 与 GPU 之间实现更高效的任务分工与协作，最终促进整体帧率的提升与渲染流程的稳定。在 Unity 引擎中，可通过打开 Terrian 中的 Draw Instanced 选项、将渲染管线中 GPU Resident Drawer 设置为 Instanced
Drawing 以及开启草丛材质的 Enable GPU Instancing 选项启用该技术。

\subsection{手势和面部动态捕捉}

本系统采用MediaPipe方案进行实时手势关键点检测与面部动态捕捉。MediaPipe作为轻量级、跨平台的解决方案，能够在普通摄像头下实现稳定的实时识别，适合展览场景部署。

\textbf{系统架构}：整个捕捉系统采用事件驱动的模块化架构，主要包含三个核心组件。\textbf{HandDetector}和\textbf{FaceDetector}分别运行在独立的守护线程中，负责从摄像头捕获帧并进行关键点检测；检测器内部维护状态机，仅在检测状态变化时生成事件，避免每帧发送冗余数据。事件通过\textbf{EventBus}（基于Python的queue.Queue实现线程安全队列）发布，形成生产者—消费者模型。\textbf{TcpSender}在后台线程中运行asyncio事件循环，从EventBus消费事件并通过TCP协议发送至智能体服务端。这种解耦设计使得检测器与网络发送逻辑完全独立，异常处理完善，网络错误不影响检测流水线正常运行。

\textbf{手部检测器}：基于MediaPipe HandLandmarker模型，支持21个手部关键点检测。检测器内部维护状态机，状态转换路径为：\texttt{NO\_HAND} $\rightarrow$ \texttt{HAND\_PRESENT} $\rightarrow$ \texttt{PINCH} $\rightarrow$ \texttt{PINCH\_RELEASED} $\rightarrow$ \texttt{NO\_HAND}。支持的手势事件包括：\texttt{hand\_detected}（手部首次出现）、\texttt{hand\_lost}（手部完全消失）、\texttt{pinch}（拇指与食指捏合，触发时附带平均坐标）、\texttt{pinch\_released}（捏合释放）、\texttt{open\_both\_hands}（左右手同时张开）、\texttt{swipe\_left}与\texttt{swipe\_right}（手腕快速左右滑动）。关键算法方面，捏合检测通过计算拇指尖（landmark 4）和食指尖（landmark 8）的欧氏距离实现，阈值设为0.06（归一化坐标）；手部张开检测检查所有指尖（landmark 8, 12, 16, 20）与手腕（landmark 0）的距离；滑动手势则通过跟踪手腕X坐标的速度，超过阈值时触发。

\textbf{面部检测器}：基于MediaPipe FaceLandmarker模型，检测468个面部关键点。检测器以鼻尖位置（landmark 1）作为面部中心参考点，维护简单的布尔状态（\texttt{face\_present}或\texttt{face\_absent}）。支持的事件包括：\texttt{face\_detected}（面部首次出现，附带鼻尖坐标）、\texttt{face\_lost}（面部完全消失）。与手部检测器相同，面部检测器也采用状态机驱动，仅在面部出现/消失状态变化时发布事件，避免每帧发送冗余数据。

\textbf{统一事件格式}：所有检测器共享的\textbf{UnifiedEvent}数据结构包含以下属性：\texttt{source}（事件来源，"hand"或"face"）、\texttt{event}（事件名称）、\texttt{data}（字典类型，包含位置坐标、置信度分数等）、\texttt{timestamp\_ms}（事件时间戳，毫秒级）。事件通过JSON格式序列化后，经TCP协议发送至智能体服务端，协议采用长度前缀（4字节大端序无符号整数）+ UTF-8编码JSON载荷的二进制帧格式。

MediaPipe客户端同样以TCP Client方式连接至智能体服务端，上报识别结果。

\subsection{场景布置}

技能图标使用矢量绘图工具（Affinity）绘制四个音符图案，采用贝塞尔曲线（Bézier Curve）构建流畅的音符轮廓线条。贝塞尔曲线是一种广泛应用于计算机图形学的参数曲线，通过控制点定义曲线形态。本设计使用三次贝塞尔曲线（cubic Bézier），其数学表达式为$B(t) = (1-t)^3P_0 + 3(1-t)^2tP_1 + 3(1-t)t^2P_2 + t^3P_3$，其中$P_0$、$P_1$、$P_2$、$P_3$为控制点，$t \in [0,1]$为参数。通过调整中间控制点$P_1$、$P_2$的位置，可以灵活控制曲线的弯曲方向与曲率，使音符图案呈现出自然、优美的线条形态。矢量绘图完成后，将图案缩放到合适比例打印在A4纸上，粘贴于椴木板，使用美工刀雕刻出镂空图形，最后用装饰性麻绳串联并固定于展台。整体场景布置注重实体装置与虚拟界面的视觉呼应。

\subsection*{章节状态追踪实现}

状态追踪模块负责监控参展者在三个章节中的进度和情感状态，其核心算法基于多模态特征融合和章节特定的转换条件。

\textbf{（1）多模态特征提取与章节特征映射}

系统从四个维度提取特征向量，并映射到三个章节的特定特征：
\begin{itemize}
    \item \textbf{第一章特征}：手势稳定性（捏合持续时间）、探索频率、方向选择犹豫度
    \item \textbf{第二章特征}：情绪波动性、社交互动频率、边界维护成功率
    \item \textbf{第三章特征}：知识吸收速度、未知耐受度、创造表达频率
    \item \textbf{通用特征}：交互频率、注意力集中度、情感强度
\end{itemize}

特征融合采用章节特定的加权算法：
$$S_t^{(c)} = \sum_{i=1}^{n} w_i^{(c)} \cdot f_i^{(c)}$$
其中$S_t^{(c)}$为章节$c$在时刻$t$的状态评分，$f_i^{(c)}$为章节$c$的第$i$个特征，$w_i^{(c)}$为章节特定的权重。

\textbf{（2）章节状态概率计算}

系统维护三个章节状态的概率分布$P(c|S_t^{(c)})$，其中$c \in \{\text{第一章}, \text{第二章}, \text{第三章}\}$。章节状态概率通过softmax函数计算：
$$P(c|S_t^{(c)}) = \frac{\exp(v_c \cdot S_t^{(c)} + d_c)}{\sum_{c'}\exp(v_{c'} \cdot S_t^{(c')} + d_{c'})}$$
权重向量$v_c$和偏置$d_c$通过监督学习训练得到。

\subsection*{章节化决策生成机制}

决策模块基于当前章节、子状态和感知输入生成协调的多模态反馈。系统采用三层决策结构，对应三个章节的情感叙事需求：

\textbf{（1）反应层决策：即时交互反馈}

对即时交互生成快速反馈，决策逻辑基于章节特定的规则匹配：

\begin{verbatim}
# 第一章：自我锚定反馈
if gesture == "pinch" and chapter == 1:
    if current_substate == "迷茫":
        trigger_guidance("尝试持续奏响音符")
        visual_feedback = "山峦轻微抖动"
    elif current_substate == "锚定中":
        trigger_note_playback("waterdrop")
        adjust_lighting(color="blue", intensity=0.6)
        visual_feedback = "山体局部固化"

# 第二章：关系边界反馈  
if emotion == "overwhelmed" and chapter == 2:
    trigger_boundary_protection()
    adjust_lighting(color="purple", mode="pulse")
    visual_feedback = "建筑停止挤压"

# 第三章：知识驾驭反馈
if cognitive_load == "high" and chapter == 3:
    simplify_feedback()
    adjust_music(tempo="slow")
    visual_feedback = "潮水波动减缓"
\end{verbatim}

反应层决策延迟控制在50-100ms，确保交互的即时性。

\textbf{（2）策略层决策：章节进度管理}

基于章节进度和短期交互历史生成策略性反馈。策略层维护章节特定的有限状态机：

\begin{itemize}
    \item \textbf{第一章策略}：关注自我认知进度，调整引导强度和谜题难度
    \item \textbf{第二章策略}：关注关系平衡状态，调整社交互动密度和边界保护
    \item \textbf{第三章策略}：关注知识吸收节奏，调整未知暴露程度和创造空间
\end{itemize}

策略层根据章节目标动态调整：
\begin{enumerate}
    \item \textbf{进度落后时}：增加引导提示，降低谜题难度
    \item \textbf{进度超前时}：增加隐藏内容，提升挑战性
    \item \textbf{情感偏离时}：调整环境氛围，引导回归主题
    \item \textbf{认知超载时}：简化交互，提供休息机会
\end{enumerate}

\textbf{（3）叙事层决策：情感成长引导}

管理三个章节的情感叙事发展，控制整体成长弧线。叙事层决策基于多目标强化学习框架，奖励函数设计为：
$$R = \alpha \cdot E_{\text{self}} + \beta \cdot E_{\text{relation}} + \gamma \cdot E_{\text{world}} + \delta \cdot E_{\text{flow}}$$
其中：
\begin{itemize}
    \item $E_{\text{self}}$：自我认知奖励（基于第一章进度）
    \item $E_{\text{relation}}$：关系探索奖励（基于第二章进度）
    \item $E_{\text{world}}$：世界接纳奖励（基于第三章进度）
    \item $E_{\text{flow}}$：心流体验奖励（基于注意力集中度）
\end{itemize}

叙事层决策确保三个章节的情感成长形成完整弧线：
\begin{enumerate}
    \item \textbf{第一章终点}：参展者应建立基本的自我认知和锚定能力
    \item \textbf{第二章终点}：参展者应理解关系平衡和边界维护
    \item \textbf{第三章终点}：参展者应获得知识驾驭和创造自由
    \item \textbf{整体弧线}：从迷茫被动到主动创造的情感蜕变
\end{enumerate}

\subsection*{章节化自适应调整机制}

    \item \textbf{认知风格}：直觉型（整体把握）vs 分析型（细节关注）
    \item \textbf{学习节奏}：快速型（迅速掌握）vs 渐进型（需要重复）
\end{itemize}

\textbf{动态难度调整算法}：

系统根据参展者表现动态调整章节难度：
$$D_c = D_{\text{base}} + \alpha \cdot P_{\text{success}} - \beta \cdot T_{\text{struggle}} + \gamma \cdot E_{\text{engagement}}$$
其中：
\begin{itemize}
    \item $D_c$：章节$c$的当前难度
    \item $D_{\text{base}}$：基础难度
    \item $P_{\text{success}}$：成功率调整因子
    \item $T_{\text{struggle}}$：挣扎时间调整因子
    \item $E_{\text{engagement}}$：参与度调整因子
\end{itemize}

\textbf{个性化叙事节奏控制}：

系统根据观众特征调整三个章节的时间分配：
\begin{verbatim}
def adjust_chapter_timing(player_profile):
    # 基础时间分配（分钟）
    base_timing = {"chapter1": 15, "chapter2": 20, "chapter3": 25}
    
    # 根据特征调整
    if player_profile["style"] == "激进型":
        base_timing["chapter1"] *= 0.8  # 缩短第一章
        base_timing["chapter3"] *= 1.2  # 延长第三章
    elif player_profile["style"] == "谨慎型":
        base_timing["chapter1"] *= 1.3  # 延长第一章
        base_timing["chapter2"] *= 0.9  # 缩短第二章
        
    if player_profile["emotion"] == "外倾型":
        base_timing["chapter2"] *= 1.2  # 延长社交章节
    elif player_profile["emotion"] == "内倾型":
        base_timing["chapter2"] *= 0.8  # 缩短社交章节
        
    return base_timing
\end{verbatim}

\textbf{情感支持机制}：

当系统检测到参展者情感困扰时，提供章节特定的支持：
\begin{itemize}
    \item \textbf{第一章困扰}：提供更明确的自我锚定引导，简化谜题
    \item \textbf{第二章困扰}：降低社交压力，提供边界保护提示
    \item \textbf{第三章困扰}：减少未知暴露，提供知识结构框架
    \item \textbf{整体困扰}：调整叙事节奏，提供情感共鸣内容
\end{itemize}

这种章节化的自适应调整机制确保《回声之境》能为不同特征的观众提供个性化的情感成长体验，在保持核心叙事完整性的同时，适应多样化的交互需求和情感状态。

\begin{itemize}

    \item \textbf{本系统方法}：单VLM（视觉语言模型）结合结构化技能（SKILL）体系，通过Tool Calling机制实现多功能集成

状态追踪是目标导向交互的核心技术，两种方法在状态追踪的实现上各有特点：

\begin{itemize}

    \item \textbf{本系统方法}：基于情感状态图的隐式状态建模，状态转换通过多模态特征融合和概率计算实现
    \item \textbf{适用场景}：论文方法更适合任务导向的对话交互，本系统方法更适合情感导向的展览体验
\end{itemize}

两种方法都致力于平衡交互自主性与叙事连贯性，但侧重点不同：

\begin{itemize}
    \item \textbf{论文方法}：通过状态图提供结构化框架，在框架内允许自由对话，强调“强自主性”
    \item \textbf{本系统方法}：通过情感状态引导和自适应反馈，在保持情感叙事连贯性的前提下支持个性化探索

\chapter{总结与展望}

\section{工作总结}

完成这一整套面向实体展览的沉浸式多模态交互系统的设计与实现，是一项工程量庞大且涉及多学科知识的复杂工作。本课题从实体展览交互体验的现实问题出发，设计并实现了一套以Unity游戏引擎为核心、以大语言模型智能体为决策中枢的沉浸式多模态交互系统《回声之境》。本毕业设计基本完成了预定的各项研究任务，以下从多个维度对本次毕业设计进行总结。

\subsection*{系统架构层面}

本系统采用”感知层—决策层—执行层”的三层星型拓扑架构，实现了多源数据的统一汇聚与分发。感知层由手势识别、面部情绪识别与交互应用状态同步三大模块构成，各模块通过TCP协议以独立客户端身份连接至决策中枢，实现了模块间的松耦合设计。决策层以Qwen3.5 VLM为基座模型，结合LangChain/DeepAgent框架实现Tool Calling能力，使模型能够根据参展者当前的手势、情绪与交互应用状态自主调用外部工具函数，完成从感知到决策的闭环。执行层则由Unity客户端与树莓派物理装置组成，分别承担虚拟场景渲染与实体灯光控制的任务。这种架构设计使得整个系统的扩展性与可维护性得到了保障，新增感知模块或执行设备仅需实现标准的TCP Client接口即可无缝接入。

\subsection*{网络通信层面}

在通信协议的设计上，本系统经历了从二进制协议到JSON文本协议的演进过程，最终确定采用长度前缀（4字节大端序）+ UTF-8编码JSON载荷的协议格式。该协议支持四种消息类型（text、image、command、register），通过统一的字段结构封装所有数据载荷。协议设计过程中充分权衡了解析效率与可维护性：JSON文本形式便于开发阶段的调试与日志分析，而Base64编码虽然增加了约33\%的体积，但在本机与局域网环境下网络带宽充足、延迟极低，实际使用中完全可以接受。此外，Unity客户端通过异步发送机制与信号量（Semaphore）实现线程安全的发送控制，避免了TCP粘包与数据交错问题。

\subsection*{智能体实现层面}

智能体是本系统的核心决策模块，其与TCP Server深度耦合，采用生产者—消费者模式处理消息队列。在框架选型上，采用DeepAgent（基于LangChain/LangGraph）作为智能体框架，利用其内置的规划与任务分解能力、文件系统中间件支持的上下文管理能力以及子代理嵌套机制，完成了VLM与外部工具的有机结合。系统定义了六个核心工具函数（\texttt{control\_lights}、\texttt{send\_to\_client}、\texttt{advance\_game\_chapter}、\texttt{trigger\_game\_event}、\texttt{play\_music}、\texttt{set\_environment}），VLM可根据感知信息自主选择调用，实现对虚拟场景与物理设备的协同控制。在可观测性方面，系统集成了OpenTelemetry与Phoenix链路追踪，支持多层次的分层日志输出与端到端的Tool Calling过程可视化，为智能体行为的调试与优化提供了有力支撑。

\subsection*{交互应用层面}

《回声之境》作为本课题的交互应用载体，在设计上融合了情感化理念与空间叙事手法。游戏中的四个音符——水滴（waterdrop）、道路交错（crossing）、海浪（tide）、风（breeze）——不仅是演奏与视觉反馈的载体，更是旅人理解世界、塑造世界的方式，映射了从认识自我、到处理他人关系、再到汲取知识、最终获得自由的成长路径。在技术实现上，旅人动画通过状态机与新输入系统驱动，草地场景采用NPR着色模型与GPU Instancing优化，相机系统基于Cinemachine的Spline Dolly实现富有叙事感的轨道式跟随，音符UI动效则借助DOTween实现获取与演奏的差异化时序编排。

\subsection*{实体装置层面}

实体装置的设计注重虚拟与现实的视觉呼应。技能图标使用Affinity矢量绘图工具绘制四个音符图案，采用贝塞尔曲线构建流畅的音符轮廓线条，雕刻于椴木板后配合麻绳串联固定于展台。灯条控制通过树莓派加PWM控制器实现，作为TCP Client连接至智能体服务端，实时响应来自决策模块的灯光控制指令，实现与虚拟场景的同步变化。

\section{主要贡献与创新点}

综合上述工作，本系统的主要贡献与创新点可以归纳为以下三个方面：

\begin{enumerate}
\item \textbf{轻量化数据需求}：不同于Lumine等研究需要数千小时的标注交互数据，本系统基于现成VLM的零样本能力，仅需少量场景-决策对应关系即可运行，大幅降低了数据收集与标注成本，使系统在有限资源下仍具备快速部署的能力。
\item \textbf{多模态融合决策}：系统同时整合视觉（手势、面部情绪）、交互应用内部状态以及上下文记忆，通过VLM做出综合决策，而非传统系统的单一模态简单映射。这种融合决策机制使系统能够更准确地理解参展者的整体状态，输出更贴合情境的响应。
  \item \textbf{物理世界交互}：系统不仅控制交互叙事的推进与虚拟场景的视觉变化，还能实时影响展厅内的物理设备（LED灯阵等），通过TCP通信驱动树莓派PWM控制器实现灯光的动态变化，真正实现了虚拟世界与现实空间的无缝融合，使展览交互体验从屏幕内延伸至实体空间。
\end{enumerate}

\section{不足与反思}

尽管本次毕业设计基本完成了预定目标，但在实际开发过程中也暴露出若干不足之处，值得在后续工作中加以改进。

\begin{enumerate}
\item \textbf{交互应用内容深度不足}：由于开发时间与个人精力有限，《回声之境》在叙事内容、关卡设计与情感表达等方面仍有较大的打磨空间。四个音符的象征意义与交互机制的结合尚不够紧密，部分场景的情绪基调与交互反馈之间的关联度可以进一步提升。
\item \textbf{情绪识别精度有限}：当前系统采用现成的MediaPipe方案进行手势与面部关键点检测，情绪状态的量化维度较为单一，尚未充分利用面部关键点的时序变化实现更细腻的情感推断。
\item \textbf{实体装置与虚拟场景的同步精度}：目前灯条控制与交互应用内事件之间存在一定的响应延迟，实体装置的物理反馈与虚拟画面的时间一致性尚有优化空间。如需提升至展览级别的用户体验，需在通信延迟优化与同步策略设计上做更多工作。
\item \textbf{智能体的决策可解释性}：尽管系统集成了Phoenix链路追踪工具，但VLM在Tool Calling决策过程中的推理逻辑仍像一个”黑箱”，难以向非技术用户解释为何在某一时刻选择了特定的工具调用。在面向普通观众的展览场景中，增加决策的可解释性将有助于提升用户对系统的信任感。
\end{enumerate}

\section{未来展望}

展望未来，本系统可从以下几个方向进行拓展与深化：

在模型层面，尽管本系统使用了通用的视觉语言模型作为决策智能体的基座模型，但具身智能、智能眼镜等前沿领域已涌现出许多更适合空间推理的模型架构，例如腾讯混元实验室推出的Spatial-TTT，解决了长时序视频输入的空间理解问题。将其应用于实体展览，有望进一步提高交互系统的模型决策精度，使系统能够更好地理解用户在实体空间中的行为意图。

在交互模态层面，当前系统的感知通道主要包括手势、面部情绪与交互应用状态。未来可进一步引入语音交互、目光注视追踪或心率传感等更多模态，实现更丰富的多模态融合决策，使系统能够更全面地感知观众的心理状态与交互需求。

在内容层面，交互应用的叙事深度与关卡设计仍有较大的拓展空间。未来的版本可以进一步挖掘四个音符的象征意义，设计更丰富的演奏组合与场景变化，使音乐真正成为塑造交互应用世界面貌的核心力量，同时为观众带来更具情感深度与艺术感染力的沉浸式体验。

总之，本次毕业设计为构建更具情感连接与沉浸感的公共展览交互体验提供了可行的技术路径与设计参考，也为后续的持续优化与实际落地应用奠定了基础。
