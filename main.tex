\begin{chineseabstract}
随着虚拟现实、人工智能等数字技术的快速发展，人机交互正逐步从以键盘、鼠标为主的单一输入范式，转向融合多感知通道的沉浸式交互形态。然而，当前实体展览中的公共交互装置仍存在交互方式趋同、情感反馈缺失、体验深度不足等问题。本文针对上述问题，设计并实现了一套面向实体展览的沉浸式多模态交互系统。系统以Unity游戏引擎为核心交互平台，整合了手势识别、面部情绪识别、游戏状态感知等多源信息，并基于大语言模型智能体（Qwen3.5 + DeepAgent）构建中央决策模块，实现对虚拟场景与物理装置（LED灯阵、音效等）的协同控制。本文详细阐述了系统的总体架构、网络通信协议、智能体工具调用机制、关键视觉与交互模块的实现方法，并展示了实体装置的设计与集成。本系统为构建更具情感连接与沉浸感的公共展览交互体验提供了可行的技术路径与设计参考。

\begin{englishabstract}
With the rapid development of digital technologies such as virtual reality and artificial intelligence, human-computer interaction is gradually shifting from a single input paradigm dominated by keyboards and mice to an immersive interaction paradigm that integrates multiple sensory channels. However, current public interactive installations in physical exhibitions still suffer from homogenized interaction methods, lack of emotional feedback, and insufficient experience depth. To address these issues, this thesis designs and implements an immersive multimodal interaction system for physical exhibitions. The system uses Unity game engine as the core interaction platform, integrating multi-source information such as gesture recognition, facial emotion recognition, and game state perception, and constructs a central decision-making module based on large language model agents (Qwen3.5 + DeepAgent) to achieve coordinated control of virtual scenes and physical devices (LED arrays, sound effects, etc.). This thesis elaborates on the system's overall architecture, network communication protocols, agent tool-calling mechanisms, implementation methods of key visual and interaction modules, and demonstrates the design and integration of physical devices. This system provides a feasible technical path and design reference for constructing more emotionally connected and immersive public exhibition interactive experiences.

\chapter{绪论}

\section{研究背景}

随着虚拟现实、人工智能等数字技术的快速发展，现代人机交互方式正逐步从以键盘、鼠标为主的单一输入范式，转向融合多感知通道的沉浸式交互形态。公共交互装置作为现代城市空间与博物展览中的新兴艺术表达媒介，致力于构建人与作品之间的深度对话\citing{wen2022huadong}，而上述技术进步为其体验深度与表现形式拓展了新的可能。

从当今的实体展览的现状来看，实体展览逐渐从藏品陈列和静态信息呈现的展示模式，向强调观众参与和体验感受的方向演进。博物馆等机构持续致力于优化其与观众的互动方式，特别是在观众与文物、艺术品等展品的交互层面，当代博物馆与艺术展厅致力于打破“请勿触摸”的传统禁锢，转而追求更具实践性、叙事性与沉浸感的互动体验。

然而，当前展览中的公共交互装置在交互体验上仍存在明显不足。一方面，部分系统仅简单引入数字屏幕与触控交互，参观者的体验与操作普通电子设备无异，未能充分发挥实体展览特有的现场感与空间优势。另一方面，由于设计范式趋同，许多装置的交互方式、反馈逻辑与视觉表现呈现同质化倾向，难以有效促进参与者的情感投入与持续探索，导致可互动但不耐体验的现象。这使得互动装置未能充分实现其作为展览媒介应有的情感沟通与意义建构价值，观众与作品之间难以建立稳定而深入的联系。

\section{研究意义}

针对上述问题，本课题引入游戏引擎技术作为核心开发平台。Unity等现代游戏引擎凭借其卓越的实时渲染、场景管理与图形处理能力，使高性能、高复杂度的三维空间表现和实时反馈成为可能，为交互式视觉内容的构建提供了强大的平台支持。通过借鉴成熟的电子游戏交互机制与空间叙事方法，可以有效反哺现实展览系统，增强其趣味性与体验深度。

在多模态情感识别技术方面，随着深度学习在计算机视觉与运动捕捉领域的广泛应用，系统能够精准捕捉用户的身体姿态、手势及面部表情。相较于传统控制器，这种具身化的交互方式能更自然地映射用户的心理状态，从而实现更高维度的情感化沉浸体验。与此同时，人类对计算机情感理解与交互的需求愈加广泛。根据中国科学院科技战略咨询研究院发布的《2021年研究前沿热度指数》报告，“多模态情感计算”相关研究热度指数位居前列。

在此背景下，围绕实体展览场景，开展多模态沉浸式交互系统的设计研究，对于重构用户体验、创新情感反馈机制、探索技术融合应用具有重要的现实意义。

\chapter{国内外研究现状}

\section{多模态交互技术研究进展}

多模态交互是一种变革性的人机交互方法，允许用户通过语音、手势、触控、注视和触觉等多种输入与输出模态与系统进行交互。随着传感器技术和机器学习的进步，多模态系统在虚拟助手、智能环境、医疗保健和辅助技术等各类应用中日益重要。

\begin{figure}[htbp]
  \centering
  \includegraphics[width=0.8\textwidth]{pic/Gemini_Generated_Image_lb4363lb4363lb43.png}
  \caption{多模态交互分类}
  \label{fig:mm-classification}
\end{figure}

如图\ref{fig:mm-classification}所示，多模态系统涉及不同层面：在模态层面，涵盖视觉、听觉、触觉等多种感官形式；在技术层面，包括手势识别、语音识别、运动传感、虚拟现实等软硬件解决方案；在学习与干预层面，则关注如何通过系统设计支持用户的认知、情感与技能发展。多模态交互技术结合数据融合算法，允许用户通过自然手势、语音指令等方式与虚拟展品互动，从而提升参与的直观性与沉浸感。通过加权融合来自不同传感器的数据，系统可以更准确地解读用户意图。

近年来，大模型技术的迅速发展为情感识别提供了全新的研究范式。

\begin{figure}[htbp]
  \centering
  \includegraphics[width=0.8\textwidth]{pic/截屏2026-01-09 18.51.42.png}
  \caption{情感识别大模型分析维度}
  \label{fig:emotion-lm}
\end{figure}

如图\ref{fig:emotion-lm}所示，吴敖等人的《情感识别大模型研究综述》将多模态情感识别分为统一编码、层次化融合和生成式模型三种架构。统一编码架构将不同模态或任务的异构数据映射到一个统一的语义表示空间中，具有很高的挑战性。例如张艺媛等人提出的Meta-Transformer能将多达12种模态统一映射到参数冻结的Transformer编码器，显著减少了新模态的对齐参数量，实现广泛模态兼容性。

对于本课题的具体需求，由于按钮序列、虚拟空间内事件信息较为简单，可直接使用固定算法处理，因此可以单独针对视觉信息使用单模态情感识别模型，再进行融合计算。单模态情感识别模型优势在于计算开销小，同时在特定受限场景下能实现很高的情感识别准确率。

面部表情作为最直接的视觉情感表达载体，能够精确反映个体的情绪状态。近期的学术研究包括分层窗口机制、预训练ViT、双流协作机制等。然而，高精度面部解码存在明显局限性，在面对遮挡、低分辨率或复杂情感时，其分析能力会显著下降。当面部信息不明确时，肢体动作便成为解读情感强度与行为意图的关键线索。本课题中，面部表情和肢体动作的视觉识别均采用成熟的工业级方案（如MediaPipe、DeepFace等），以快速搭建可用环境并方便集成于展览系统。

当前的智能体通常依赖强化学习在封闭环境中完成单一目标，缺乏泛化能力和实时交互能力。2025年ByteDance发布的Lumine工作首次实现了在3D开放世界游戏中完成小时级任务的能力，展现了视觉语言模型（VLM）在复杂交互场景中的巨大潜力。尽管本系统的目标是面向展览的交互系统，但其与通用GUI智能体及具身智能领域的VLA（视觉-语言-动作）模型一脉相承。

\section{实体展览交互装置研究进展}

现有研究指出，一套完整的博物馆交互展览系统通常包含数据层、逻辑层与展示层三层架构。其中，展示层负责提供高保真的三维渲染与多模态交互界面，支持用户在实体空间中以多样方式与虚拟内容互动。本课题的设计与实现聚焦于展示层的构建与优化。

互动装置艺术作为连接展览内容与观众的关键媒介，其价值不仅在于满足基础的视听需求，更在于营造用户在参与过程中生理、心理乃至精神层面的综合情感体验。温文龙等学者基于互动仪式链理论指出\citing{wen2022huadong}，通过预设具有规范性、表演性与趣味性的互动仪式，可以为参与者创造特定的体验情境。

\begin{figure}[htbp]
  \centering

  \caption{互动仪式理论与互动装置的要素适配}
  \label{fig:ritual}

如图\ref{fig:ritual}所示，在仪式化的互动过程中，情感能量得以产生、分享与传递，并通过”仪式链”的连续性维持高强度的参与体验，这为互动装置的情感化设计提供了理论依据。

情感化设计是一种将人的情感需求放在首位的设计方式。李静雅、温文龙等研究者分别从实验验证与设计应用层面证实了情感化设计在提升用户参与度和满意度方面的重要性。本课题旨在将这一思路延伸至通用展览场景，通过多模态交互强化装置的情感沟通与意义建构能力，从而在观众与作品之间建立更稳固的深层连接。

在具体设计实践方面，李静雅等人通过TouchDesigner软件实验，提出了节奏与视觉形态关联的音乐可视化模型（圆形—慢节奏、方形—中节奏、三角形—快节奏），为视听联觉反馈设计提供了参考，也为本课题交互作品《回声之境》的视觉生成逻辑提供了实证依据。

此外，交互装置的核心技术基础在于其输入设备与交互方式。Manca Ogrizek等人的研究表明，在博物馆的虚拟现实交互中，为机械结构复杂的交互任务提供实体工具，能对用户体验产生积极影响。这支撑了本课题实体装置与虚拟反馈结合的设计路线。

\section{游戏引擎在沉浸式体验中的技术应用}

视觉生成的历史可追溯至20世纪70年代 J. B. Mitroo 等人的音乐可视化研究，采用彩色光栅图形显示器生成音符、和弦及和弦进行的可视化图像，如图2所示\citing{mitroo1979music}。

而在当今，游戏引擎已成为构建沉浸式虚拟环境与交互系统的核心工具。程序化视觉生成技术利用算法动态创建视觉内容，在现代游戏设计与计算机图形学中常用于高效生成地形、纹理或动态效果。该技术能够根据实时输入参数驱动视觉元素的形态、颜色与运动规律变化，从而实现内容表现的无限多样性与自适应特性，非常适合用于创造个性化、响应式的展览视觉体验。Unity与Unreal Engine等引擎提供了强大的图形渲染、物理模拟、音频处理与脚本逻辑支持，极大地降低了复杂交互应用的开发门槛，并已广泛应用于数字展览和互动艺术领域\citing{kruger2024gameengines}。

如图3展示了Epic Games公司在旗下《堡垒之夜》游戏中举办的虚拟演唱会中，通过根据演出内容实时改变场景、角色Shader和后期处理参数，实现了华丽且富有感染力的演出效果，取得了良好口碑和极为可观的传播效果。

\chapter{系统总体设计}

\section{需求分析}

本系统面向实体展览场景，旨在构建一套沉浸式多模态交互系统。主要需求包括：

\begin{enumerate}
\item \textbf{多模态感知能力}：能够实时捕捉用户的手势、面部情绪，并同步游戏内部状态。
\item \textbf{智能决策能力}：基于多源信息，实现情感驱动的动态反馈决策。
\item \textbf{虚实融合执行能力}：能够同时控制虚拟场景中的视觉、音效表现，以及实体空间中的灯光等物理装置。
\item \textbf{模块化与可扩展性}：各模块松耦合，便于独立开发、调试与后续扩展。
\item \textbf{实时性与稳定性}：满足展览场景下的低延迟响应与长时间稳定运行要求。
\end{enumerate}

\section{系统实现方案}

在确定系统架构后，本节具体说明各模块的技术选型与实现概要。

在开题阶段，本课题规划了系统的研究路线与实现步骤。首先，通过文献研究法广泛收集并分析实体展览、交互装置设计、多模态交互、情感计算及程序化生成技术等相关文献，为系统设计提供理论基础。其次，在理论分析的基础上开展关键技术验证与前期实验：搭建并训练面向面部表情与动态手势的情感识别模型，探索实时可视化与程序化视觉生成的核心算法。再次，进行多模态交互系统的集成设计与开发，完成Unity核心场景搭建与关卡设计，实现多模态输入与系统反馈的整合，驱动虚拟场景的程序化视觉变化与物理LED灯阵的同步光影反馈。最后，在系统实现过程中持续进行迭代测试与优化，通过用户测试评估系统的流畅性、沉浸感与情感传达效力，最终完成整个系统的原型构建与效果展示。

\subsection*{Unity引擎与交互应用}

经前期调研，选用Unity引擎作为交互应用载体。Unity凭借其卓越的实时渲染、场景管理与图形处理能力，能够支撑高性能、高复杂度的三维空间表现和实时反馈需求。

\textbf{旅人动画系统}：在完成整体章节印象设计和旅人形象构想后，使用Gemini + Nano Banana生成旅人的美术形象，其后使用字节跳动的Seed 3D生成带PBR材质的旅人3D模型，在Blender中完成骨骼绑定和权重绘制，并制作简单的走路动画。完成后导出FBX模型并导入Unity，使用Animator状态机、Character Controller及新输入系统共同实现旅人的移动控制与动画驱动。

\textbf{轨道摄像机系统}：采用Unity的Cinemachine插件实现程序化相机控制。将相机的行为抽象层与物理相机相分离，通过Spline Dolly模式使相机沿预设样条曲线移动，配合Rotation Composer模式动态追踪旅人，并引入Basic Multi Channel Perlin噪声为相机轨迹添加微震动效果，实现富有叙事感的轨道式跟随镜头。

\textbf{风格化渲染}：远景山峦采用半透明抖动着色器，通过菲涅尔效应实现边缘发光与半透明效果，结合顶点着色器随机偏移营造山峦起伏的朦胧意境，隐喻旅人方向感未定；草地场景通过顶点着色器中的连续噪声函数实现随风摆动的动态效果。两者均采用非真实感渲染（NPR）技法，营造《回声之境》独特的视觉风格。

\textbf{音符交互系统}：旅人在旅程中可获得四个音符，每个音符对应不同的视觉与音效反馈。音符演奏时触发场景元素的程序化变化——水滴音符固化未定元素、道路交错音符引发空间分叉与连接、海浪音符驱动潮汐式流动、风音符则使声音传遍整个回声之境。音符UI动效使用DOTween插件实现获取与演奏的差异化时序编排，通过颜色过渡与发光脉冲循环营造节奏感。

\subsection*{实体装置}

实体装置旨在将虚拟世界的交互状态延伸至物理空间，增强观展者的沉浸感与具身参与体验。

\textbf{技能图标实体化}：将游戏中的四个音符图标实体化，使用椴木板制作展览实物。图标图案采用矢量绘图工具（Affinity Designer）绘制四次贝塞尔曲线构建流畅的音符轮廓线条，经雕刻、镂空处理后配合装饰性麻绳串联固定于展台。实体图标与游戏内的点亮状态保持同步，当玩家在游戏中演奏音符时，对应图标同步亮起LED灯效。

\textbf{灯光控制系统}：灯条采用WS2812可编程RGB LED灯带，具有单点可控、色彩丰富、响应速度快的特点。灯带由树莓派通过PWM（脉冲宽度调制）信号控制，树莓派作为TCP Client连接至智能体服务端，接收来自Agent的灯光控制指令（颜色、亮度、闪烁模式），实时驱动灯带产生与虚拟场景同步的动态光影效果。

\textbf{信号传递流程}：实体装置的信号链路为：MediaPipe/Unity感知模块 → TCP上报 → Agent决策 → TCP下发控制指令 → 树莓派PWM驱动LED。树莓派接收到控制指令后，通过Python的rpi-ws281x库将PWM信号转换为LED灯带的显示效果，实现从虚拟场景到实体空间的跨媒介联动。

\textbf{「那位没有过去，却正被未来召唤的人」}

\chapter{制作流程与实现}

\section{网络通信实现}

在分布式多模态交互系统中，各模块间的通信效率与可靠性直接影响系统的实时响应能力与用户体验。本节详细阐述系统网络通信的整体架构、协议设计演进过程以及关键实现机制。

\subsection*{通信架构概述}

系统采用TCP/IP协议实现模块间通信。决策模块（智能体服务端）与TCP Server一体化部署，作为通信中枢接收来自各感知模块的数据上报，并将决策指令下发至执行模块。Unity客户端、MediaPipe客户端、树莓派客户端等感知与执行模块均作为TCP客户端连接至决策中枢。这种星型拓扑结构实现了各模块的松耦合设计：各感知模块仅需关注自身数据采集，无需了解其他模块的存在；决策模块则充当统一的信息汇聚与分发中心，负责协调各模块间的数据流转。

在通信协议的选择上，本系统经过深入比较，最终确定采用TCP Socket而非WebSocket作为传输层协议。TCP Socket相比WebSocket具有更低的协议开销和传输延迟，且能够提供更精细的流量控制与连接管理能力。此外，TCP Socket支持更底层的网络配置选项，便于针对展览场景的特定需求进行优化调参。

\subsection*{协议设计演进}

在协议格式的设计过程中，本系统经历了从二进制协议到JSON文本协议的演进历程。

\textbf{（1）二进制协议方案}

早期设计采用长度前缀+消息类型的二进制协议格式，具体结构为：4字节大端序无符号整数表示载荷长度，1字节无符号整数表示消息类型（\texttt{0x00=TEXT}、\texttt{0x01=IMAGE}、\texttt{0x02=COMMAND}、\texttt{0x03=REGISTER}），其后为载荷数据。这种二进制协议在理论上具有最高的解析效率，但在实际开发中暴露出若干问题：由于图片数据与文本数据采用完全不同的编码方式，智能体在处理混合类型消息时需要额外的类型判断与解码逻辑，增加了中间件的开发复杂度；此外，二进制协议的调试与维护也较为困难，难以在开发阶段进行直观的协议检查。

\textbf{（2）JSON文本协议方案}

基于上述实践经验，本系统最终采用长度前缀+UTF-8编码的JSON协议格式。该协议将所有数据统一封装为JSON对象，包含以下四个核心字段：

\begin{itemize}
\item \texttt{type}：消息类型，取值为 \texttt{text}（普通文本消息）、\texttt{image}（Base64编码的图片数据）、\texttt{command}（控制命令）、\texttt{register}（客户端注册）
\item \texttt{data}：载荷内容，文本消息时为UTF-8字符串，图片消息时为Base64编码的二进制数据
\item \texttt{client\_type}：发送者身份标识，取值包括 \texttt{echoagent}（智能体）、\texttt{unity}（Unity客户端）、\texttt{mediapipe}（感知模块）、\texttt{raspberry\_pi}（树莓派控制端）
\item \texttt{request\_id}：请求追踪标识，采用UUID格式，用于关联请求与响应
\end{itemize}

该协议格式具有以下优势：JSON的文本形式便于开发阶段的调试与日志分析；统一的数据封装方式简化了智能体端的协议解析逻辑；Base64编码虽然增加了约33\%的数据体积，但换取了协议的一致性与可维护性。考虑到本系统运行于本机与局域网环境下，网络带宽充足且延迟极低（通常低于5ms），上述开销在实际使用中完全可以接受。

\subsection*{Unity客户端的线程安全发送机制}

Unity引擎基于单线程执行模型，其生命周期方法（如 \texttt{Update}、\texttt{FixedUpdate}等）均在主线程中运行。然而，TCP网络通信涉及I/O操作，为避免阻塞主线程导致帧率下降，本系统在 \texttt{AgentCommunicator} 组件中采用了异步发送机制，并通过信号量（Semaphore）实现线程安全的发送控制。

具体实现上，\texttt{SendRawAsync} 方法采用 \texttt{SemaphoreSlim} 作为发送锁，确保在同一时刻仅有一个发送任务持有网络流的使用权。当多个协程或异步任务同时发起发送请求时，发送锁保证这些请求被串化执行，避免TCP粘包或数据交错问题。锁的获取与释放位于 \texttt{try-finally} 块中，确保即使在网络异常情况下也能正确释放资源，防止死锁发生。

此外，\texttt{AgentCommunicator} 通过 \texttt{SynchronizationContext} 将接收到的网络消息投递回Unity主线程执行回调，从而在不影响游戏帧率的前提下完成消息的解析与分发。这种设计在保持网络通信高效性的同时，确保了所有游戏逻辑均在主线程中执行，符合Unity的线程安全要求。

\section{智能体EchoAgent实现}

作为为《回声之境》服务的智能体，本文将其命名为 EchoAgent。EchoAgent 内部基于大语言模型构建，作为整个系统的决策层和中枢节点。TCP Socket 服务器与 EchoAgent 之间通过一个异步消息队列进行通信：服务器负责接收来自各类客户端（Unity、MediaPipe、Raspberry Pi 等）的消息，并将它们投入共享的消息队列；EchoAgent 则定时从队列中批量取出消息，经大语言模型理解后，自主决策并调用相应工具完成响应。

在系统启动流程上，本设计先创建全局消息队列，再创建 TCP 服务器并注入该队列的引用，最后创建 EchoAgent 实例，使其同时持有队列与服务器的引用。这种顺序确保了各组件在初始化时能够正确建立关联。

由于智能体需要主动向各个已连接的客户端发送消息或命令，本系统将这类操作封装为可被大语言模型调用的工具（Tools）。这里存在一个设计上的矛盾：工具的参数必须是字符串或数字等简单类型，以便大语言模型生成，然而向客户端发消息这一操作本质上需要持有 TCP 服务器实例的引用。为解决这一矛盾，本系统利用面向对象的闭包特性，在 EchoAgent 初始化时将 TCP 服务器实例保存为其成员属性，而工具函数则作为内部方法定义，通过隐式绑定到 \texttt{self} 来访问服务器实例，从而在不破环工具参数类型约束的前提下实现了对服务器的控制。

整个系统运行时，TCP 服务器与 EchoAgent 各自在独立的无限循环中运作：TCP 服务器持续监听端口、接收并解析来自客户端的消息，同时暴露发送消息的接口供外部调用；EchoAgent 则按固定时间间隔（默认五秒）批量取出消息队列中积压的所有消息，交由大语言模型进行理解与推理，再由模型自主选择并调用合适的工具完成响应。

\subsection{DeepAgent}

本系统采用 \textbf{DeepAgent} 框架，基座模型采用 \textbf{Qwen3.5-Plus}。DeepAgent基于LangGraph和LangChain构建，具备深度的规划能力、高效的上下文管理及灵活的子代理委派机制，可通过\texttt{write\_todos}工具自动拆解复杂任务并动态调整执行计划；自动记忆压缩有效解决超长任务带来的上下文溢出问题；支持通过\texttt{task}工具实时创建子代理，在实现复杂功能的同时保持主代理上下文的简洁高效；无缝对接LangGraph的状态管理与LangSmith的监控、评估与部署能力。

\subsection{技能（SKILL）设计}

在大语言模型智能体的实际部署中，如何让模型有效理解任务环境并执行相应操作，是一个核心问题。传统的方案通常依赖提示词工程（Prompt Engineering），通过自然语言描述向智能体传递系统知识。然而，这种方式存在显著局限：提示词长度受限、描述易产生歧义、模型对结构化信息的理解效率远高于自由文本。

基于上述考量，本系统设计了一套专用的技能，通过结构化的机器可读格式向智能体传递系统知识，使智能体能够准确掌握交互系统的架构细节、通信协议、感知能力与可控设备。

\textbf{（1）系统架构描述模型}

SKILL体系首先定义了系统的层次化架构模型。本系统采用“感知层—决策层—执行层”的三层星型拓扑结构，其中感知层包含手势识别、面部情绪识别与游戏状态同步三个独立模块，各模块均以TCP Client方式向决策层上报数据；决策层以Qwen3.5 VLM为基座模型，结合DeepAgent框架实现Tool Calling能力；执行层则由Unity客户端与树莓派物理装置组成。SKILL中通过结构化字段明确各层的职责边界与数据流向，使智能体能够理解其在系统中的定位与作用。

\textbf{（2）标准化通信协议抽象}

智能体与各模块间的通信遵循标准化的JSON-over-TCP协议。SKILL对协议格式进行了形式化描述，包括消息类型体系（text、image、command、register四种消息类型）、客户端身份标识（echoagent、unity、mediapipe、raspberry\_pi）、以及请求追踪机制（request\_id字段用于关联请求与响应）。这种形式化描述使得智能体能够精确理解每条消息的语义，而非依赖自然语言的模糊表述。

\textbf{（3）感知事件模型}

感知层各模块上报的事件是智能体决策的主要输入来源。SKILL定义了一套统一的事件模型：每个事件包含来源标识（source）、事件名称（event）、事件数据（data，含位置坐标、置信度等）以及时间戳（timestamp\_ms）。在此基础上，SKILL进一步描述了各感知模块的具体事件类型与触发条件。

对于手势识别模块，定义了手部出现/消失、捏合（pinch）、捏合释放、双手张开、左右滑动手势等事件，并说明了捏合检测的算法原理——通过计算拇指尖（landmark 4）与食指尖（landmark 8）的欧氏距离实现，阈值设为0.06。对于面部识别模块，则定义了面部出现/消失事件，以鼻尖位置作为参考点。通过这种结构化描述，智能体能够准确判断当前收到的感知数据代表何种交互状态。

\textbf{（4）工具函数接口规范}

Tool Calling是智能体控制外部设备的唯一途径。SKILL定义了六个核心工具函数，每个函数包含功能描述、参数列表与返回值约定。工具函数的设计遵循“单一职责”原则：\texttt{control\_lights}负责灯光控制（颜色、亮度、模式三个参数）；\texttt{send\_to\_client}负责向指定客户端转发消息；\texttt{advance\_game\_chapter}与\texttt{trigger\_game\_event}分别用于游戏叙事控制；\texttt{play\_music}与\texttt{set\_environment}则分别控制音频与视觉环境。参数类型均采用简单字符串或数值，避免复杂嵌套结构，降低VLM解析出错概率。

\textbf{（5）上下文感知与交互策略}

单纯的实时响应不足以构建连贯的交互体验，智能体还需理解游戏叙事上下文与用户情感趋势。SKILL定义了上下文记忆的管理规范：智能体应维护最近五轮交互历史、当前游戏章节与场景信息、玩家已获音符列表、以及情绪变化趋势。这些信息共同构成了决策的上下文基础。

在交互策略层面，SKILL定义了触发—响应的映射规则。当检测到手势捏合时，智能体根据当前场景决定触发音符演奏或场景交互；当情绪检测为正向时，灯光采用暖色调并提升亮度，音乐节奏加快；当情绪检测为负向时，则采用冷色调并降低亮度。这种规则化的策略描述使得智能体的决策行为具有可预测性与可解释性。

\textbf{（6）系统约束边界}

为防止智能体产生异常行为，SKILL还定义了系统级的约束边界，包括实时性要求（手势响应延迟低于100ms、灯光控制延迟低于200ms）、技术部署约束（仅支持局域网环境）以及内容安全限制（四个音符须按序获得、情绪反馈须柔和避免强刺激）。这些约束作为智能体决策的边界条件，确保系统在可控范围内运行。

\subsection{调试与可观测性}

\subsection{轨道摄像机}

\textbf{Cinemachine}是Unity引擎中一套功能完备的程序化相机控制模块。其核心设计理念在于将相机的行为抽象层与实际物理相机相分离，实现高度灵活且可组合的镜头系统。在本课题中，Cinemachine主要用于实现旅人跟随功能，使画面表现更具叙事性和电影感。

具体实现上，首先在场景中设置一个基准Camera，并为其挂载\textbf{Cinemachine Brain}组件，该组件负责管理虚拟相机之间的切换。随后创建\textbf{Cinemachine Camera}实体，并对其Procedural Components进行配置：\textbf{Position Control}设为\textbf{Spline Dolly}模式，使相机能够沿预设路径移动；\textbf{Rotation Control}设为\textbf{Rotation Composer}模式，用于动态调整相机旋转角度以保持对目标的追踪；\textbf{Noise}采用\textbf{Basic Multi Channel Perlin}配置，为相机轨迹添加可控的微震动效果，增强画面层次感与真实度。

进一步地，在场景中构建一条\textbf{Spline（样条曲线）}路径，并将Cinemachine Camera的Spline Dolly组件与该样条曲线绑定，约束相机的移动范围。设置\textbf{Automatic Dolly}功能，选择\textbf{Nearest Point To Target}跟随策略，使相机自动定位至样条曲线上距追踪目标最近的点位。综合上述配置，相较于传统直接跟随模式，基于样条曲线的轨道式跟随机制可实现更加平滑且富有叙事感的镜头运动，显著提升画面表现的电影化程度。

\subsection{风格化渲染}

在本课题的交互作品《回声之境》中，远景山峦与草地场景采用非真实感渲染（NPR）技术实现风格化的视觉表现，核心通过顶点着色器偏移与菲涅尔效应营造独特的画面氛围。

在Unity基于URP渲染管线中，可使用Cg或HLSL语言编写着色器，也可使用节点式的可视化编辑工具ShaderGraph。将风速、风强度、噪声纹理缩放、草地区域色彩值等设置为可实时调整的材质属性，以便后续结合多模态情感识别结果进行动态变化。

\textbf{（1）半透明抖动山峦着色器}

场景中的远景山峦承担着视觉引导与情感暗示的双重职责——它们半透明、边缘模糊，暗示着旅人自己的"方向感"仍未成形。着色器通过菲涅尔效应与顶点随机偏移实现这一表现。

\textbf{菲涅尔材质}：采用Schlick近似公式计算菲涅尔因子：

$$F_{R} = F_{0} + (1 - F_{0}) \cdot (1 - \cos\theta)^{5}$$

其中 $F_{0}$ 为基础反射率，$\theta$ 为视线方向与表面法线的夹角。当 $\theta$ 增大时，菲涅尔因子趋近于1，使山峦边缘呈现明亮的发光效果；而接近正对视角的区域则保持较高的透明度，呈现出轮廓模糊、若隐若现的质感。这一特性使山峦在深色背景下呈现出柔和而富有层次感的轮廓线，隐喻着旅人对前路的迷茫与探寻。

\textbf{顶点着色器随机偏移}：山峦的抖动效果在顶点着色器中实现。通过引入基于时间的连续噪声函数，对每个顶点进行随机的微小偏移，形成起伏不定的轮廓形态。这种不稳定性并非对现实中山峦的模拟，而是对旅人内心状态的外化——方向未定、前路未明，山峦的每一次颤动都映照着角色内心的徘徊与探寻。

\textbf{Uniform参数控制}：为方便外部动态控制山峦的视觉表现，着色器预留了四个可调参数：

\begin{itemize}
    \item \textbf{FresnelPower}（Float）：控制菲涅尔效应的衰减速率，较小的值使边缘发光范围更大，较大的值使发光集中在更窄的边缘区域；
    \item \textbf{FresnelColor}（Color）：定义边缘发光的颜色，可根据场景氛围调整（如淡蓝、暖橙或银白）；
    \item \textbf{WobbleSpeed}（Float）：控制抖动动画的时间节奏，较快的速度产生轻微颤动，较慢的速度产生缓慢起伏；
    \item \textbf{WobbleIntensity}（Float）：控制抖动的幅度大小，决定山峦轮廓的模糊程度。
\end{itemize}

上述参数通过C\#脚本直接引用材质对象进行动态修改。在Unity中，可通过 \texttt{GetComponent<Renderer>().material} 获取材质实例，并使用 \texttt{material.SetFloat()}、\texttt{material.SetColor()} 等方法实时调整参数值。这种方式便于与智能体模块对接，智能体可通过标准化接口直接向渲染模块下发参数调整指令，实现山峦视觉表现随情绪氛围的动态变化。

\textbf{（2）草地动态效果}

草地场景的动态效果本质上是草丛几何体顶点的规律性偏移，需要在顶点着色器上操作。为模拟随风摆动的动态，最核心的工具是连续噪声函数，其数学目标是构造一个连续可导、局部相关、全局随机的函数 $N(x,y,z) \in [-1,1]$。相比真正的随机数，它满足偏导数 $\partial N / \partial x \neq 0$ 且变化平滑。如图\ref{fig:noise-2d}所示，这是一张满足上述要求的在二维空间上分布的噪声图像，将其灰度值线性映射到 $[-1,1]$ 区间即可表示风力大小。将噪声函数的位移值随时间移动采样，构建滚动纹理，即可作用于草丛的顶点偏移形成摆动效果。

\subsection{现实空间动态灯光实现}

\subsection{手势和面部动态捕捉}

本系统采用MediaPipe方案进行实时手势关键点检测与面部动态捕捉。MediaPipe作为轻量级、跨平台的解决方案，能够在普通摄像头下实现稳定的实时识别，适合展览场景部署。

\textbf{系统架构}：整个捕捉系统采用事件驱动的模块化架构，主要包含三个核心组件。\textbf{HandDetector}和\textbf{FaceDetector}分别运行在独立的守护线程中，负责从摄像头捕获帧并进行关键点检测；检测器内部维护状态机，仅在检测状态变化时生成事件，避免每帧发送冗余数据。事件通过\textbf{EventBus}（基于Python的queue.Queue实现线程安全队列）发布，形成生产者—消费者模型。\textbf{TcpSender}在后台线程中运行asyncio事件循环，从EventBus消费事件并通过TCP协议发送至智能体服务端。这种解耦设计使得检测器与网络发送逻辑完全独立，异常处理完善，网络错误不影响检测流水线正常运行。

\textbf{手部检测器}：基于MediaPipe HandLandmarker模型，支持21个手部关键点检测。检测器内部维护状态机，状态转换路径为：\texttt{NO\_HAND} $\rightarrow$ \texttt{HAND\_PRESENT} $\rightarrow$ \texttt{PINCH} $\rightarrow$ \texttt{PINCH\_RELEASED} $\rightarrow$ \texttt{NO\_HAND}。支持的手势事件包括：\texttt{hand\_detected}（手部首次出现）、\texttt{hand\_lost}（手部完全消失）、\texttt{pinch}（拇指与食指捏合，触发时附带平均坐标）、\texttt{pinch\_released}（捏合释放）、\texttt{open\_both\_hands}（左右手同时张开）、\texttt{swipe\_left}与\texttt{swipe\_right}（手腕快速左右滑动）。关键算法方面，捏合检测通过计算拇指尖（landmark 4）和食指尖（landmark 8）的欧氏距离实现，阈值设为0.06（归一化坐标）；手部张开检测检查所有指尖（landmark 8, 12, 16, 20）与手腕（landmark 0）的距离；滑动手势则通过跟踪手腕X坐标的速度，超过阈值时触发。

\textbf{面部检测器}：基于MediaPipe FaceLandmarker模型，检测468个面部关键点。检测器以鼻尖位置（landmark 1）作为面部中心参考点，维护简单的布尔状态（\texttt{face\_present}或\texttt{face\_absent}）。支持的事件包括：\texttt{face\_detected}（面部首次出现，附带鼻尖坐标）、\texttt{face\_lost}（面部完全消失）。与手部检测器相同，面部检测器也采用状态机驱动，仅在面部出现/消失状态变化时发布事件，避免每帧发送冗余数据。

\textbf{统一事件格式}：所有检测器共享的\textbf{UnifiedEvent}数据结构包含以下属性：\texttt{source}（事件来源，"hand"或"face"）、\texttt{event}（事件名称）、\texttt{data}（字典类型，包含位置坐标、置信度分数等）、\texttt{timestamp\_ms}（事件时间戳，毫秒级）。事件通过JSON格式序列化后，经TCP协议发送至智能体服务端，协议采用长度前缀（4字节大端序无符号整数）+ UTF-8编码JSON载荷的二进制帧格式。

MediaPipe客户端同样以TCP Client方式连接至智能体服务端，上报识别结果。

\subsection{场景布置}

技能图标使用矢量绘图工具（Affinity）绘制四个音符图案，采用贝塞尔曲线（Bézier Curve）构建流畅的音符轮廓线条。贝塞尔曲线是一种广泛应用于计算机图形学的参数曲线，通过控制点定义曲线形态。本设计使用三次贝塞尔曲线（cubic Bézier），其数学表达式为$B(t) = (1-t)^3P_0 + 3(1-t)^2tP_1 + 3(1-t)t^2P_2 + t^3P_3$，其中$P_0$、$P_1$、$P_2$、$P_3$为控制点，$t \in [0,1]$为参数。通过调整中间控制点$P_1$、$P_2$的位置，可以灵活控制曲线的弯曲方向与曲率，使音符图案呈现出自然、优美的线条形态。矢量绘图完成后，将图案缩放到合适比例打印在A4纸上，粘贴于椴木板，使用美工刀雕刻出镂空图形，最后用装饰性麻绳串联并固定于展台。整体场景布置注重实体装置与虚拟界面的视觉呼应。

\section{工作总结}

完成这一整套面向实体展览的沉浸式多模态交互系统的设计与实现，是一项工程量庞大且涉及多学科知识的复杂工作。本课题从实体展览交互体验的现实问题出发，设计并实现了一套以Unity游戏引擎为核心、以大语言模型智能体为决策中枢的沉浸式多模态交互系统《回声之境》。本毕业设计基本完成了预定的各项研究任务，以下从多个维度对本次毕业设计进行总结。

\subsection*{系统架构层面}

本系统采用”感知层—决策层—执行层”的三层星型拓扑架构，实现了多源数据的统一汇聚与分发。感知层由手势识别、面部情绪识别与游戏状态同步三大模块构成，各模块通过TCP协议以独立客户端身份连接至决策中枢，实现了模块间的松耦合设计。决策层以Qwen3.5 VLM为基座模型，结合LangChain/DeepAgent框架实现Tool Calling能力，使模型能够根据玩家当前的手势、情绪与游戏状态自主调用外部工具函数，完成从感知到决策的闭环。执行层则由Unity客户端与树莓派物理装置组成，分别承担虚拟场景渲染与实体灯光控制的任务。这种架构设计使得整个系统的扩展性与可维护性得到了保障，新增感知模块或执行设备仅需实现标准的TCP Client接口即可无缝接入。

\subsection*{网络通信层面}

在通信协议的设计上，本系统经历了从二进制协议到JSON文本协议的演进过程，最终确定采用长度前缀（4字节大端序）+ UTF-8编码JSON载荷的协议格式。该协议支持四种消息类型（text、image、command、register），通过统一的字段结构封装所有数据载荷。协议设计过程中充分权衡了解析效率与可维护性：JSON文本形式便于开发阶段的调试与日志分析，而Base64编码虽然增加了约33\%的体积，但在本机与局域网环境下网络带宽充足、延迟极低，实际使用中完全可以接受。此外，Unity客户端通过异步发送机制与信号量（Semaphore）实现线程安全的发送控制，避免了TCP粘包与数据交错问题。

\subsection*{智能体实现层面}

智能体是本系统的核心决策模块，其与TCP Server深度耦合，采用生产者—消费者模式处理消息队列。在框架选型上，采用DeepAgent（基于LangChain/LangGraph）作为智能体框架，利用其内置的规划与任务分解能力、文件系统中间件支持的上下文管理能力以及子代理嵌套机制，完成了VLM与外部工具的有机结合。系统定义了六个核心工具函数（\texttt{control\_lights}、\texttt{send\_to\_client}、\texttt{advance\_game\_chapter}、\texttt{trigger\_game\_event}、\texttt{play\_music}、\texttt{set\_environment}），VLM可根据感知信息自主选择调用，实现对虚拟场景与物理设备的协同控制。在可观测性方面，系统集成了OpenTelemetry与Phoenix链路追踪，支持多层次的分层日志输出与端到端的Tool Calling过程可视化，为智能体行为的调试与优化提供了有力支撑。

\subsection*{交互应用层面}

《回声之境》作为本课题的交互应用载体，在设计上融合了情感化理念与空间叙事手法。游戏中的四个音符——水滴（waterdrop）、道路交错（crossing）、海浪（tide）、风（breeze）——不仅是演奏与视觉反馈的载体，更是旅人理解世界、塑造世界的方式，映射了从认识自我、到处理他人关系、再到汲取知识、最终获得自由的成长路径。在技术实现上，旅人动画通过状态机与新输入系统驱动，草地场景采用NPR着色模型与GPU Instancing优化，相机系统基于Cinemachine的Spline Dolly实现富有叙事感的轨道式跟随，音符UI动效则借助DOTween实现获取与演奏的差异化时序编排。

\subsection*{实体装置层面}

实体装置的设计注重虚拟与现实的视觉呼应。技能图标使用Affinity矢量绘图工具绘制四个音符图案，采用贝塞尔曲线构建流畅的音符轮廓线条，雕刻于椴木板后配合麻绳串联固定于展台。灯条控制通过树莓派加PWM控制器实现，作为TCP Client连接至智能体服务端，实时响应来自决策模块的灯光控制指令，实现与虚拟场景的同步变化。

\section{主要贡献与创新点}

综合上述工作，本系统的主要贡献与创新点可以归纳为以下三个方面：

\begin{enumerate}
\item \textbf{轻量化数据需求}：不同于Lumine等研究需要数千小时的标注游戏数据，本系统基于现成VLM的零样本能力，仅需少量场景-决策对应关系即可运行，大幅降低了数据收集与标注成本，使系统在有限资源下仍具备快速部署的能力。
\item \textbf{多模态融合决策}：系统同时整合视觉（手势、面部情绪）、游戏内部状态以及上下文记忆，通过VLM做出综合决策，而非传统系统的单一模态简单映射。这种融合决策机制使系统能够更准确地理解玩家的整体状态，输出更贴合情境的响应。
\item \textbf{物理世界交互}：系统不仅控制游戏剧情的推进与虚拟场景的视觉变化，还能实时影响展厅内的物理设备（LED灯阵等），通过TCP通信驱动树莓派PWM控制器实现灯光的动态变化，真正实现了虚拟世界与现实空间的无缝融合，使展览交互体验从屏幕内延伸至实体空间。
\end{enumerate}

\section{不足与反思}

尽管本次毕业设计基本完成了预定目标，但在实际开发过程中也暴露出若干不足之处，值得在后续工作中加以改进。

\begin{enumerate}
\item \textbf{游戏内容深度不足}：由于开发时间与个人精力有限，《回声之境》在叙事内容、关卡设计与情感表达等方面仍有较大的打磨空间。四个音符的象征意义与游戏机制的结合尚不够紧密，部分场景的情绪基调与交互反馈之间的关联度可以进一步提升。
\item \textbf{情绪识别精度有限}：当前系统采用现成的MediaPipe方案进行手势与面部关键点检测，情绪状态的量化维度较为单一，尚未充分利用面部关键点的时序变化实现更细腻的情感推断。
\item \textbf{实体装置与虚拟场景的同步精度}：目前灯条控制与游戏内事件之间存在一定的响应延迟，实体装置的物理反馈与虚拟画面的时间一致性尚有优化空间。如需提升至展览级别的用户体验，需在通信延迟优化与同步策略设计上做更多工作。
\item \textbf{智能体的决策可解释性}：尽管系统集成了Phoenix链路追踪工具，但VLM在Tool Calling决策过程中的推理逻辑仍像一个”黑箱”，难以向非技术用户解释为何在某一时刻选择了特定的工具调用。在面向普通观众的展览场景中，增加决策的可解释性将有助于提升用户对系统的信任感。
\end{enumerate}

\section{未来展望}

展望未来，本系统可从以下几个方向进行拓展与深化：

在模型层面，尽管本系统使用了通用的视觉语言模型作为决策智能体的基座模型，但具身智能、智能眼镜等前沿领域已涌现出许多更适合空间推理的模型架构，例如腾讯混元实验室推出的Spatial-TTT，解决了长时序视频输入的空间理解问题。将其应用于实体展览，有望进一步提高交互系统的模型决策精度，使系统能够更好地理解用户在实体空间中的行为意图。

在交互模态层面，当前系统的感知通道主要包括手势、面部情绪与游戏状态。未来可进一步引入语音交互、目光注视追踪或心率传感等更多模态，实现更丰富的多模态融合决策，使系统能够更全面地感知观众的心理状态与交互需求。

在内容层面，游戏的叙事深度与关卡设计仍有较大的拓展空间。未来的版本可以进一步挖掘四个音符的象征意义，设计更丰富的演奏组合与场景变化，使音乐真正成为塑造游戏世界面貌的核心力量，同时为观众带来更具情感深度与艺术感染力的沉浸式体验。

总之，本次毕业设计为构建更具情感连接与沉浸感的公共展览交互体验提供了可行的技术路径与设计参考，也为后续的持续优化与实际落地应用奠定了基础。
