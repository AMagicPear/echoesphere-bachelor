\begin{chineseabstract}
随着虚拟现实、人工智能等数字技术的快速发展，人机交互正逐步从以键盘、鼠标为主的单一输入范式，转向融合多感知通道的沉浸式交互形态。然而，当前实体展览中的公共交互装置仍存在交互方式趋同、情感反馈缺失、体验深度不足等问题。本文针对上述问题，设计并实现了一套面向实体展览的沉浸式多模态交互系统。系统以Unity引擎为核心交互平台，整合了手势识别、面部情绪识别、交互应用状态感知等多源信息，并基于大语言模型智能体（Qwen3.6 + DeepAgent）构建中央决策模块，实现对虚拟场景与物理装置（LED灯阵、音效等）的协同控制。本文详细阐述了系统的总体架构、网络通信协议、智能体工具调用机制、关键视觉与交互模块的实现方法，并展示了实体装置的设计与集成。本系统为构建更具情感连接与沉浸感的公共展览交互体验提供了可行的技术路径与设计参考。

\chinesekeyword{多模态交互；游戏引擎；智能体；情感计算；实体展览}
\end{chineseabstract}

\begin{englishabstract}
With the rapid development of digital technologies such as virtual reality and artificial intelligence, human-computer interaction is gradually shifting from a single input paradigm dominated by keyboards and mice to an immersive interaction paradigm that integrates multiple sensory channels. However, current public interactive installations in physical exhibitions still suffer from homogenized interaction methods, lack of emotional feedback, and insufficient experience depth. To address these issues, this thesis designs and implements an immersive multimodal interaction system for physical exhibitions. The system uses Unity engine as the core interaction platform, integrating multi-source information such as gesture recognition, facial emotion recognition, and application state perception, and constructs a central decision-making module based on large language model agents (Qwen3.6 + DeepAgent) to achieve coordinated control of virtual scenes and physical devices (LED arrays, sound effects, etc.). This thesis elaborates on the system's overall architecture, network communication protocols, agent tool-calling mechanisms, implementation methods of key visual and interaction modules, and demonstrates the design and integration of physical devices. This system provides a feasible technical path and design reference for constructing more emotionally connected and immersive public exhibition interactive experiences.

\englishkeyword{Multimodal Interaction; Game Engine; Agent; Affective Computing; Physical Exhibition}
\end{englishabstract}

\chapter{绪论}

\section{研究背景}

在日常的数字交互中，无论是个人电脑上的电子游戏，还是移动设备上的各类应用，人们的交互方式长期依赖键盘、鼠标、手柄或触摸屏等传统输入设备，而系统的反馈也大多局限于屏幕内部的视觉变化与扬声器发出的音效；而另一方面，当谈及沉浸式体验时，公众的第一反应又往往将其与虚拟现实头戴设备联系在一起，似乎只有将用户从物理空间中完全剥离、置入一个由头显构建的虚拟环境，才称得上真正的沉浸。然而，这种将沉浸式体验与虚拟现实等同的认知恰恰忽略了实体空间本身所具有的不可替代价值。在博物展览与公共艺术装置等真实场景中，参观者身处物理空间，其身体在场性、空间感知能力与多感官协同体验是任何头戴式设备无法完全复现的。更重要的是，实体展览中的参观者无需佩戴额外设备即可自然移动、观察和感受，其社交行为不受遮挡，使得多人共享体验以及更深刻的情感联结成为可能。

从当今实体展览的发展态势看，其也正亟待引入更具沉浸的交互方式。公共交互装置作为现代城市空间与博物展览中的新兴艺术表达媒介，致力于构建人与作品之间的深度对话\citing{wen2022huadong}。当今的展览模式正逐渐从藏品陈列和静态信息呈现，向强调观众参与和体验感受的方向演进，博物馆等机构也持续致力于打破“请勿触摸”的传统禁锢，转而追求更具实践性、叙事性与沉浸感的互动体验\citing{ogrizek2024vr}\citing{jiang2024dunhuang}。但遗憾的是，当前展览中的公共交互装置在交互体验上仍存在明显不足：一方面，部分系统仅简单引入数字屏幕与触控交互，参观者的体验与操作普通电子设备无异，未能充分发挥实体展览特有的现场感与空间优势；另一方面，由于设计范式趋同，许多装置的交互方式、反馈逻辑与视觉表现呈现同质化倾向，难以有效促进参与者的情感投入与持续探索，导致可互动但不耐体验的现象。这使得互动装置未能充分实现其作为展览媒介应有的情感沟通与意义建构价值，观众与作品之间难以建立稳定而深入的联系。

事实上，在此前已有少数先锋艺术家与商业团体尝试将沉浸式体验带入真实物理空间，但这些探索大多发生在人工智能技术爆发式跃迁的前夜，其交互逻辑仍受限于预设规则与固定脚本。而近两年来，随着大语言模型与视觉语言模型的飞速发展，尤其是2026年初，以OpenClaw为代表的个人终端智能体火爆互联网的当下，这种根植于现实空间的沉浸式体验也被赋予了全新的可能。


\section{研究目的和意义}

本课题旨在借助人工智能与智能体技术，将游戏引擎与其所支撑的高品质沉浸式交互体验从虚拟现实的头盔中解放出来，带到实体展览空间之中。具体而言，本课题探索了一种将手势与面部表情纳入输入模态、将多模态智能体作为核心处理模块、将现实三维空间中的LED灯阵变化与屏幕空间内的动态视觉生成共同作为输出反馈的新型交互范式。参展者的手势动作与情绪状态被实时感知，驱动虚拟场景内的角色移动和视觉演变，同时通过物理灯光装置将这种变化延伸至整个展览空间，使沉浸感从屏幕内部扩散至物理世界。

在核心开发平台方面，本课题引入Unity引擎。Unity凭借其卓越的实时渲染、场景管理与图形处理能力，为高性能、高复杂度的三维空间表现和实时反馈提供了坚实支撑。通过借鉴成熟的电子游戏交互机制与空间叙事方法，可以有效反哺现实展览系统，增强其趣味性与深度\citing{kruger2024gameengines}。

在多模态情感识别技术方面，随着深度学习在计算机视觉与运动捕捉领域的广泛应用，系统能够精准捕捉用户的身体姿态、手势及面部表情。与此同时，人类对计算机情感理解与交互的需求愈加广泛\citing{tao2024multimodal}。相较于传统控制器，这种具身化的交互方式能更自然地映射用户的心理状态，从而实现更高维度的情感化沉浸体验。

在智能体技术层面，随着大语言模型与视觉语言模型的迅速发展，基于基础模型的智能体已成为人工智能领域的重要研究方向。智能体被定义为一类交互系统，能够感知视觉刺激、语言输入及其他环境数据，并产生有意义的具身化动作\citing{durante2024agent}。在展览交互场景中，智能体可以充当感知层与执行层之间的决策中枢：根据多模态感知输入理解用户意图，结合任务规划与常识推理生成控制指令，并通过工具调用实现对虚拟场景与物理设备的协同控制。这种”感知—决策—执行”的闭环架构为构建更具智能性的沉浸式交互系统提供了技术基础。

围绕实体展览场景，开展多模态沉浸式交互系统的设计研究，对于重构用户体验、创新情感反馈机制、探索技术融合应用具有重要的现实意义。

在虚拟沉浸式体验领域，游戏引擎技术与人工智能的融合正在催生全新的交互范式。Epic Games公司在《堡垒之夜》中举办的虚拟演唱会是一个标志性案例。如图\ref{fig:epic-concert}所示，该演出通过根据音乐内容实时改变场景Shader与后期处理参数，实现了富有感染力的视听体验，取得了良好口碑和极为可观的传播效果\citing{epic2024niagara}。这一案例展示了游戏引擎在实时视觉生成方面的强大能力，以及程序化内容生成在大型虚拟演出中的应用潜力。然而，虚拟演唱会本质上仍是一种单向的视听呈现——观众是信息的被动接收者，系统并不感知个体观众的状态，也无法根据观众反应进行实时调整。

\subsection{现有实践的局限与本课题的切入点}

综合来看，尽管上述国内外实践在实体展览交互装置与虚拟沉浸式体验方面取得了显著进展，但仍存在以下关键缺口：一是多数展览交互系统仍依赖预设规则，缺乏基于多源感知数据的实时综合决策能力；二是虚拟场景与物理装置的联动大多停留在简单的触发—响应层面，尚未实现情感驱动的协同控制；三是现有智能体方案在展览场景中的部署案例仍然稀缺，特别是将大语言模型智能体与实体装置（如LED灯阵）进行深度集成的实践探索尚属空白。

基于大语言模型的智能体被定义为能够感知视觉刺激、语言输入及其他环境数据并产生有意义动作的交互系统\citing{durante2024agent}，其“感知—决策—执行”的闭环架构为交互系统的智能化提供了清晰的技术路径。在展览交互场景中，智能体可以充当感知层与执行层之间的决策中枢：根据多模态感知输入理解用户意图，结合任务规划与常识推理生成控制指令，并通过工具调用实现对虚拟场景与物理设备的协同控制。本课题正是针对上述缺口，设计并实现了一套以游戏引擎为交互平台、以大语言模型智能体为决策中枢、以树莓派驱动物理灯光为虚实联动载体的沉浸式多模态交互系统，在展览交互的智能化决策与虚实深度融合方面进行了创新性探索。

\chapter{文献综述}

\section{实体展览交互装置研究进展}

现有研究指出，一套完整的博物馆交互展览系统通常包含数据层、逻辑层与展示层三层架构。其中，展示层负责提供高保真的三维渲染与多模态交互界面，支持用户在实体空间中以多样方式与虚拟内容互动\citing{li2024exhibition}。本课题的设计与实现聚焦于展示层的构建与优化。

互动装置艺术作为连接展览内容与观众的关键媒介，其价值不仅在于满足基础的视听需求，更在于营造用户在参与过程中生理、心理乃至精神层面的综合情感体验。温文龙等学者基于互动仪式链理论指出\citing{wen2022huadong}，通过预设具有规范性、表演性与趣味性的互动仪式，可以为参与者创造特定的体验情境。如图\ref{fig:ritual}所示，在仪式化的互动过程中，情感能量得以产生、分享与传递，并通过“仪式链”的连续性维持高强度的参与体验，这为互动装置的情感化设计提供了理论依据\citing{wen2022huadong}。

\begin{figure}[htbp]
  \centering
  \includegraphics[width=0.8\textwidth]{pic/互动仪式理论与互动装置的要素适配.png}
  \caption{互动仪式理论与互动装置的要素适配\citing{wen2022huadong}}
  \label{fig:ritual}
\end{figure}

情感化设计是一种将人的情感需求放在首位的设计方式\citing{norman2005emotional}。相关研究从实验验证与设计应用层面证实了情感化设计在提升用户参与度和满意度方面的重要性。例如，在面向特殊人群的媒体设计中，基于感官代偿理论的多模态交互已取得成熟应用。李静雅等人通过 TouchDesigner 软件实验，提出了节奏与视觉形态关联的音乐可视化模型：圆形—慢节奏、方形—中节奏、三角形—快节奏\citing{li2023music}，这为视听联觉反馈设计提供了参考，也为本课题的交互作品《回声之境》的视觉生成逻辑提供了实证依据。Valérian Fraisse 等人通过对大量文献的系统性综述，提出了一个从艺术意图、交互设计与系统设计三个视角描述交互式声音装置的概念框架，并构建了一个涵盖多维度特征的可视化数据库，揭示了该领域的研究趋势与实践多样性\citing{fraisse2021sound}，为本课题的系统性设计提供了方法论参照。本课题旨在将这一思路延伸至通用展览场景，通过多模态交互强化装置的情感沟通与意义建构能力，从而在观众与作品之间建立更稳固的深层连接。

此外，交互装置的核心技术基础在于其输入设备与交互方式。研究表明，在博物馆的虚拟现实交互中，为机械结构复杂的交互任务提供实体工具，能对用户体验产生积极影响\citing{ogrizek2024vr}。这一发现支撑了本课题实体装置与虚拟反馈结合的设计路线——在本课题展览装置设计中，将向参观者提供与交互应用内部场景相呼应的 3D 打印物件作为输入工具。

而在当今，游戏引擎已成为构建沉浸式虚拟环境与交互系统的核心工具。程序化视觉生成技术利用算法动态创建视觉内容，在现代交互应用设计与计算机图形学中常用于高效生成地形、纹理或动态效果。该技术能够根据实时输入参数驱动视觉元素的形态、颜色与运动规律变化，从而实现内容表现的无限多样性与自适应特性，非常适合用于创造个性化、响应式的展览视觉体验。Unity与Unreal Engine等引擎提供了强大的图形渲染、物理模拟、音频处理与脚本逻辑支持，极大地降低了复杂交互应用的开发门槛，并已广泛应用于数字展览和互动艺术领域\citing{kruger2024gameengines}。

\section{多模态交互与智能体技术研究进展}

多模态交互作为一种变革性的人机交互方法，允许用户通过语音、手势、触控、注视和触觉等多种输入与输出模态与系统进行交互。随着大语言模型和视觉语言模型的迅速发展，这一领域正经历从”互联网AI”向”具身智能”的范式转移——系统不再仅是信息的被动处理者，而是能够主动感知环境、理解情境并施加影响的交互主体。智能体AI作为这一范式转移的核心载体，正在重新定义展览场景中人与系统的交互关系。

\subsection{智能体AI的核心架构}

现代多模态交互系统的核心正演变为智能体AI，它被定义为一类能感知视觉刺激、语言输入及其他环境数据，并产生有意义具身动作的交互系统\citing{durante2024agent}。智能体AI强调”感知—决策—执行”的闭环架构\citing{yao2023react}：多源感知模块融合异构数据，中央决策模块基于上下文进行推理与任务规划，最终生成结构化的控制指令驱动虚拟场景与物理设备。在实体展览场景中，这一闭环意味着参展者的手势、情绪与应用状态被持续采集并汇聚至决策中枢，经综合推理后转化为对虚拟画面与物理装置的协同控制指令。

在架构层面，深度代理代表了智能体系统的进化方向，其设计目标是在长达数小时的操作周期内维持逻辑一致性。该架构主要由四大支柱构成：详细的系统提示词、规划与任务管理工具、持久性上下文管理以及分层代理委派机制。通过引入内部规划机制，智能体可将复杂目标分解为多个主要执行阶段并为每个阶段设定明确的成功标准——这种显式规划过程提高了决策透明度，并允许代理在任务执行中根据新信息动态调整策略。研究者提出的智能体变换器框架进一步将系统划分为五个功能模块：环境感知与任务规划、智能体学习、记忆、动作预测和认知\citing{durante2024agent}，为构建面向复杂交互场景的智能体系统提供了结构化指导。

视觉-语言-动作模型是智能体实现跨模态理解与执行的关键技术路径。VLA模型通过将图像、文本和动作信号统一离散化为Token序列，在共享的自回归框架下实现全模态建模，从架构层面消除了独立编码器之间的对齐障碍。UniVLA等研究表明，预训练的大规模视频数据即使不含动作标签，也可通过”世界模型”后训练策略显著提升下游策略的学习效率。受认知科学双过程理论启发，OneTwoVLA等最新工作开始探索将”自动思考”（系统1）与”受控思考”（系统2）解耦：系统1负责高频、低延迟的动作反应，系统2则在关键节点（如任务完成、错误检测）介入进行显式逻辑推理，从而在交互流畅性与决策深度之间取得平衡。这一技术路线对实体展览场景具有双重启示：在架构层面，虚实联动环境中视觉状态、行为信号与控制指令构成了紧密耦合的多模态序列，VLA类架构提供了端到端的建模可能；在交互层面，双过程设计契合了展览场景中高频手势跟随与低频情感决策共存的天然需求。

在智能体的学习方法方面，上下文学习作为大语言模型时代的新兴方法展现出有效性，少样本提示成为跨任务泛化模型输出的有效方式\citing{durante2024agent}。对于展览交互系统而言，上下文学习是最为适用的方法——通过精心设计的提示词即可实现不同展览场景的任务适配，无需大规模重新训练或收集专家演示数据。

将智能体置于展览交互的具体语境中，目标导向交互框架提供了一种将智能体推理能力与结构化叙事引导相结合的设计范式。该框架将交互过程构建为状态驱动的图结构：节点表示关键目标，边表示合法的状态转移，设计者通过定义状态转换条件控制交互进程，同时允许参展者在达成目标的过程中进行自由形式的探索。状态追踪是实现这一框架的关键技术——通过评估自然语言问题判断目标达成情况，驱动状态转换。双LLM架构是典型实现方案：对话语言模型负责生成自然灵活的交互回应，问答语言模型负责状态追踪与决策，确保交互进程符合设计意图。这种生成与决策的解耦设计，与本课题将多模态感知与VLM推理相分离的架构思路高度一致——在《回声之境》中，MediaPipe承担感知任务，Qwen3.6 VLM专注于综合推理与决策，情感状态图（迷茫→锚定、碰撞→边界、敬畏→自由）则提供了结构化的叙事引导框架。

\subsection{多模态情感计算与社交反馈}

情感是多模态交互中连接人与系统的关键纽带。情感计算旨在构建能自动感知、理解并反馈人类情感的可计算系统，使系统能够超越简单的指令-响应模式，基于对参展者情感状态的理解生成更具共情能力的反馈。

在多模态情感识别方面，最新研究如MiSTER-E框架采用专家混合架构，集成语音专家、文本专家和跨模态专家，通过学习得到的门控机制根据当前信号的可靠性动态调整各模态权重——当环境噪声导致语音特征不可靠时，文本专家的权重自动增加，从而确保情感推断的鲁棒性。相比单一模态，多模态融合能大幅提高识别准确率，尤其在存在环境噪声或部分模态缺失的情况下优势显著。此外，大语言模型在处理主观、语境敏感的情感任务中展现出巨大潜力，能够不仅识别表层表情，还能结合交互历史推理情感的深层语义——例如区分”愉悦的笑”与”讽刺的笑”——并据此调整交互策略。

从互动设计的理论视角来看，互动仪式链理论为情感化交互设计提供了有价值的框架\citing{wen2022huadong}。通过预设具有规范性、表演性与趣味性的互动仪式，可以为参展者创造特定的体验情境；在仪式化的互动过程中，情感能量得以产生、分享与传递，并通过”仪式链”的连续性维持高强度的参与体验。这一理论视角支撑了本课题《回声之境》以情感状态转换为主线的交互设计策略——将展览体验分解为从迷茫到认知、从碰撞到边界、从敬畏到自由的多个情感阶段，每个阶段的交互机制与反馈均服务于相应的情感目标，从而在观众与作品之间建立更稳固的深层连接。

\subsection{实时性优化、部署挑战与未来方向}

尽管多模态智能体技术取得了显著进展，其在实体展览等实时交互场景中的部署仍面临多重挑战。

实时性是阻碍沉浸感的首要障碍。大语言模型与视觉语言模型的计算开销导致推理延迟较高，与展览交互所需的低延迟响应之间存在显著差距。为应对这一矛盾，边缘-云协同计算范式通过将推理任务从数据中心转移至靠近数据源的边缘服务器，可实现显著的延迟降低；在模型层面，量化与裁剪可在保持精度的同时大幅降低内存占用，知识蒸馏则将大型云端模型的能力迁移至轻量级边缘变体。对于本课题所采用的系统架构，通过合理设置智能体轮询间隔与采用异步消息队列，可在一定程度上缓解延迟问题，但若需进一步提升实时性，仍需结合模型侧的压缩与边缘部署策略。

Sim2Real鸿沟是另一关键挑战。在模拟环境中学习的交互策略部署至真实物理世界时，常面临动作异质性和环境分布偏移等问题；展览场景中光照变化、参展者个体差异、设备状态波动等不确定性进一步加剧了这一鸿沟。弥合该鸿沟需要从数据采集（引入真实场景的多样化样本）、策略设计（增强策略对环境扰动的鲁棒性）与系统架构（引入运行时校准机制）三个层面协同推进。

伦理与社会影响同样不容忽视。用户极易对具有拟人化特质的多模态代理产生准社会关系，导致过度依赖或情感纠葛。在展览场景中，参展者可能将系统视为具有真实情感的对话伙伴而非由算法驱动的交互装置。为此，开发者需确保系统具备明确的身份披露机制与价值观对齐机制，防止系统产生不当的情感诱导或行为引导。

总体而言，多模态交互正从简单的”指令驱动”向”主动服务”转型。未来的展览交互系统将通过整合感官上下文、长期记忆与战略推理，构建具有共情能力的数字孪生实体，为参展者提供更具深度与温度的沉浸式体验。

\chapter{需求分析与总体设计}

\section{系统需求分析}

本课题面向实体展览场景，旨在构建一套沉浸式多模态交互系统。通过对展览交互场景的深入分析，系统需满足以下核心需求：

\begin{enumerate}
\item \textbf{多模态感知能力}：能够实时捕捉用户的手势、面部情绪，并同步交互应用内部状态。
\item \textbf{智能决策能力}：基于多源信息，实现情感驱动的动态反馈决策。
\item \textbf{虚实联动能力}：能够同时控制虚拟场景中的视觉、音效表现，以及实体空间中的灯光等物理装置。
\item \textbf{情感化设计}：交互设计以情绪变化为导向，将展览体验分解为多个情感状态节点（如迷茫、探索、共鸣、自由），基于状态转换规则生成相应的反馈。
\item \textbf{模块化与可扩展性}：各模块松耦合，便于独立开发、调试与后续扩展。
\item \textbf{实时性与稳定性}：满足展览场景下的低延迟响应与长时间稳定运行要求。
\end{enumerate}

\section{交互设计理念与艺术设计}

在未来，人们与虚拟世界的交互方式将不仅停留在传统的键盘鼠标输入，而会拥有更多的交互类型。本项目旨在探索一种由人工智能驱动的，富有趣味性的新型交互方式，结合实体的按钮装置和玩家情绪，在虚拟世界和现实世界中做出相应的图形图像变化，并以此作为核心的交互手段来设计交互应用的关卡。

基于上述设计理念，以下为核心设计要点：

\subsection{场景情绪基调}

《回声之境》交互应用具有叙事性质，伴随着参展者情绪变化和交互应用节奏的推进，在不同阶段设计了不同情绪基调的场景。在每个场景内，旅人的音符音色和音阶会适应场景而变化，力求营造富有诗意的参观体验。


\subsection{叙事结构与手法}

《回声之境》的故事隐喻了作者步入大学以来的心路历程。作品通过旅人的旅程，探讨自我认知、成长与未来召唤的主题。

应用设置三个章节，分别为初域·未定之原、聚落群·彼方的光影之城、深流之径·未被触及的知识海。

\subsection{旅人人物形象设计}

\textbf{「那位没有过去，却正被未来召唤的人」}

没有人知道旅人从何而来。当他睁开眼时，正立于”未定之原”的浅雾中，风声像未完成的句子，光像正在犹豫的记忆。

他没有名字，不是因为遗忘，而是因为他从未真正拥有过。旅人不是被放逐，也不是被召唤。他之所以存在，是因为回声之境”正在形成”，而只有那些\textbf{心中仍在寻找自我形状的人}，才会在世界未成形之时走进它。

在他胸口，有一块微弱跳动的光核——不是心脏，而是\textbf{他尚未理解的自己}。随着他前行，光会改变颜色、节奏与温度，它既是力量，又是负担；既是答案，又是疑问本身。旅人来到这里，是因为他已走到人生某个模糊的分叉：不再属于过去，却尚未准备好面对未来。回声之境正是这种状态的具象化。因此，旅人不是外来的闯入者，而是\textbf{这个世界尚未成形部分的化身}。

\subsection{音乐交互设计}

从应用名称《回声之境》可以看出，本设计初衷是做一个音乐驱动的互动交互应用，即 \textit{an experimental interactive application where sound shapes the world}。基于整体应用的叙事特性，场景会绑定配乐的调式和速度标识。由于不同场景运用不同调式和曲速的背景音乐，人物发出的音符若不在背景音乐的调式上会造成不协和。因此，每个交互应用场景带有固有的调式和曲速标识，参考游戏《Songbird Symphony》的设置。

\subsection{交互场景与关卡设计}

基于故事流程中的三个核心章节，本系统设计了完整的交互场景与关卡流程，确保情感叙事与交互机制的深度结合。三章分别对应”迷茫-锚定”、”碰撞-边界”、”敬畏-自由”三组情感状态的转换，各章节的交互目标与视觉意象形成一一对应的映射关系。

\subsubsection*{第一章：初域·未定之原——自我迷茫与锚定}

本章对应情感状态从”迷茫”到”锚定”的转换，核心目标是解锁水滴音符，使参展者学会在未定中锚定自我。设计理念借鉴《最后的篝火》的温柔引导机制，全程无惩罚，通过渐进式教学让参展者理解”我的声音可以塑造世界”的核心逻辑。

本章开场场景中的远景山峦承担着视觉引导与情感暗示的双重职责。半透明、边缘模糊的山峦形态隐喻着旅人尚未明晰的方向感——山峦的不稳定抖动象征着旅人内心的徘徊与探寻；当山峦被音符固化后逐渐变得坚实，则对应着旅人在迷茫中逐步锚定自我、找到方向的过程。视觉层面的虚实转换与情感层面的迷茫-锚定转变形成对照，使参展者在潜意识层面感受情绪叙事的递进。

关卡流程设计为四个阶段：参展者首先从迷雾中显现，面对半透明流动的山峦和旷野，在旁白引导下尝试与世界互动；随后在引导下按下水滴音符，山峦短暂抖动后恢复流动，仅留下水波纹光痕，参展者需持续奏响音符才能固化山体；进而进入三个方向锚点谜题——落定的石阶（过去的锚点）中需观察漂浮石块的流动规律，在合适时机奏响音符将其固化形成连续跳台；无风的山谷（当下的锚点）中需依次固化4个乱流核心，每固化一个核心，乱流减弱一分，地面起伏变小；迷雾的边界（未来的锚点）中参展者需自主判断何处应固化成山体、何处应铺成台阶，独立开辟道路；最终三个锚点全部激活后，迷雾散去，未定之原固化为稳定地貌，一条宽阔光路延伸向光影之城。

本章多模态交互设计涵盖四个维度：持续捏合手势对应持续奏响音符；发声音量对应固化范围，声音越大单次固化区域越广；山体从半透明流动态逐渐固化为坚实青青山体；水滴音符从单音变为完整短句，风声逐渐柔和。

\subsubsection*{第二章：聚落群·彼方的光影之城——关系探索与边界}

本章对应情感状态从”碰撞”到”边界”的转换，核心目标是解锁道路交错音符，使参展者学会在关系中保持自我边界。设计理念参考《最后的篝火》”中心枢纽+多分支NPC故事线”结构，每个分支对应一段社交与情感的隐喻。

旅人进入城市时，人声嘈杂导致街道挤压变窄，尝试用水滴音符无效，系统由此明确告知需要新规则。关卡设置四个分支区域：回声交汇所（相遇与连接）中，参展者帮助影子旅者连接断裂的光路，通过动作同步建立共鸣，再用水滴音符连接彼此道路；情绪风塔（共鸣与分寸）中，参展者逐层应对欢喜、悲伤、愤怒、恐惧四种情绪，学会既共情又不被吞噬；镜影回廊（他人评价与自我认知）中，参展者在布满镜面的回廊里忽略外界评价，锚定真实的自我；离别的岔路口（相遇与放下）中，参展者帮助影子旅者明白离别不是结束，各自走向自己的方向。集齐四个碎片后，城市建筑停止挤压变形，旅人脚下的路始终保持宽阔平稳。

本章核心交互机制包括：情绪折射——建筑随旅人情绪强度变化，情绪平静时建筑舒展，情绪波动时建筑扭曲；共鸣系统——与影子旅者动作同步达到80\%以上触发共鸣效果；边界保护——道路交错音符可划定自我边界，使参展者不受他人情绪影响。

\subsubsection*{第三章：深流之径·未被触及的知识海——知识接纳与自由}

本章对应情感状态从”敬畏”到”驾驭”再到”自由”的转换，核心目标是解锁海浪音符和风音符，使参展者获得完全的表达自由。设计理念体现”学得越多，未知越多”的核心命题，通过知识潮机制实现渐进式难度提升。

关卡分为浅滩区与深潮区两个阶段。浅滩区设置知识潮机制：参展者每获取一个知识碎片（对应观察、耐心、试错、联结、放下、接纳六个学习特质），潮水上涨，露出的礁石减少，但深渊光点变多更亮；集齐六个碎片后解锁海浪音符，参展者学会在知识的潮水中保持稳定。深潮区设置三道情感浪潮，分别对应迷茫、遗憾、无知三种成长困境，旅人需用已解锁的音符逐一化解；触碰海心之核后，四个音符旋律合为一首完整曲子，风音符由此解锁，参展者获得完全的表达自由。值得说明的是，开篇的晴天娃娃在深潮区回归，旅人由此明白它从未抛下自己，只是在前方等待——该设计实现叙事层面的伏笔回收。

完成深潮区挑战后，系统进入自由探索阶段，参展者可自由奏响四个音符，每个音符都会改变整个世界形态，实现无限探索可能。该阶段设计使参展者充分体验”学以致用”的成就感与”随心所欲不逾矩”的自由状态。

三章的叙事线索层层递进：第一章聚焦自我认知，未定之原是对自我迷茫的具象化；第二张聚焦关系探索，光影之城是对人际边界的具象化；第三章聚焦世界接纳，深流之径是对知识与未知态度的具象化。四个音符作为定形自我、连接他人、接纳未知、去往未来的能力象征，共同构成了旅人从迷茫走向自由的完整成长弧线。

\section{总体架构和通信协议}

基于前文的系统需求分析，本系统在架构设计上确立了以下四项核心设计原则：

\begin{enumerate}
\item \textbf{全流程多模态}：系统实现了从多模态感知（手势、面部情绪、交互应用状态）到多模态理解（VLM综合推理）再到多模态反馈（视觉、听觉、灯光）的完整闭环，各环节均以多模态数据为驱动，避免了传统系统中各模态独立处理的割裂问题。
\item \textbf{强可拓展性}：框架采用松耦合的星型拓扑结构，各感知与执行模块以统一的TCP协议接入决策中枢，能够方便地扩展更多模态信息（如心率、眼动追踪）和周围设备（如投影、音响），无需修改核心决策逻辑。
\item \textbf{虚实结合的交互体验}：传统的沉浸式体验往往与虚拟现实紧密耦合，而本系统将这种体验延伸至实体展览场景，通过虚拟画面与物理灯光装置的实时联动，使展览交互从屏幕内延伸至实体空间，实现了虚拟世界与现实空间的无缝融合。
\item \textbf{完善的调试与可观测性}：无论是智能体的Tool Calling过程还是自定义命令的收发，系统均设计了可追踪、可调试的工具链，涵盖分层日志、OpenTelemetry链路追踪及运行时调试输出，显著增强了系统的鲁棒性与开发维护效率。
\end{enumerate}

如图\ref{fig:system-arch}所示，本系统采用“感知层—决策层—执行层”的三层星型拓扑架构。

\textbf{感知层}由四个独立模块构成：MediaPipe手势识别模块负责检测参展者的手部动作（捏合、滑动、指向等）；面部情绪识别模块实时分析参展者的情感状态；Unity交互应用同步上报当前章节进度与场景事件；摄像头则提供原始视觉输入。各模块均以TCP Client方式将感知数据上报至决策层，体现了全流程多模态的设计原则——手势、表情、应用状态三类异构信息统一汇入决策中枢，而非各自独立处理。

\textbf{决策层}以EchoAgent为核心。EchoAgent内部基于大语言模型构建，结合DeepAgent框架实现Tool Calling能力，统一汇聚多源感知信息并综合推理，生成针对性的控制指令。EchoAgent与TCP Server之间通过消息队列解耦：Server负责网络通信，将接收到的客户端消息投入共享队列；EchoAgent则按固定间隔从队列中取出消息，经大语言模型理解后自主决策并调用相应工具。这种设计使决策逻辑与网络通信完全分离——EchoAgent并非TCP客户端，而是通过内部队列与Server协同，Server专注收发，Agent专注推理，二者各司其职。

\textbf{执行层}由Unity客户端与树莓派物理装置组成，分别承担虚拟场景渲染与实体灯光控制任务。这一双层执行结构是虚实结合设计原则的直接体现：同一决策指令可同时驱动虚拟画面变化与物理灯光响应，使展览交互从屏幕内延伸至实体空间，形成完整的“感知—决策—执行”闭环。

\subsection{通信架构设计}

系统采用TCP/IP协议实现模块间通信。TCP Server作为通信中枢，接收来自各感知模块的数据上报，并将决策指令下发至执行模块。Unity客户端、MediaPipe客户端、树莓派客户端及调试客户端均作为TCP Client连接至决策中枢，共同构成星型拓扑结构。这种结构实现了各模块的松耦合：各感知模块仅需关注自身数据采集，无需了解其他模块的存在；决策模块则充当统一的信息汇聚与分发中心，协调各模块间的数据流转，充分体现了强可拓展性原则——新增感知通道或执行设备只需以TCP Client接入，无需修改核心决策逻辑。

在通信协议的选择上，本系统经过深入比较，最终确定采用TCP Socket而非WebSocket作为传输层协议。TCP Socket相比WebSocket具有更低的协议开销和传输延迟，且能够提供更精细的流量控制与连接管理能力，便于针对展览场景的特定需求进行优化调参。

\subsection{协议格式设计}

在协议格式的设计过程中，本系统经历了从二进制协议到JSON文本协议的演进历程。

\textbf{（1）二进制协议方案}：早期设计采用长度前缀结合消息类型的二进制协议格式，具体结构为：4字节大端序无符号整数表示载荷长度，1字节无符号整数表示消息类型（\texttt{0x00=TEXT}、\texttt{0x01=IMAGE}、\texttt{0x02=COMMAND}、\texttt{0x03=REGISTER}），其后为载荷数据。该方案在理论上具有最高的解析效率，但在实际开发中暴露出两个问题：其一，图片数据与文本数据采用完全不同的编码路径，处理混合类型消息时需要额外的类型判断与解码逻辑，增加了开发复杂度；其二，二进制格式无法在开发阶段直接阅读，调试与问题定位均较为困难。

\textbf{（2）JSON文本协议方案}：基于上述实践经验，本系统最终采用“4字节大端序长度前缀 + UTF-8编码JSON载荷”的协议格式。发送端将JSON对象序列化为UTF-8字节序列，计算其长度并以大端序写入前4字节，随后写入载荷；接收端据此解析，确保TCP流式传输中消息边界的正确划分。该协议将所有数据统一封装为JSON对象，核心字段定义如下：

\begin{itemize}
\item \texttt{type}：消息类型，取值为 \texttt{text}（普通文本消息）、\texttt{image}（Base64编码的图片数据）、\texttt{command}（控制命令）、\texttt{register}（客户端注册）
\item \texttt{data}：载荷内容——文本消息时为UTF-8字符串，图片消息时为Base64编码的二进制数据，command类型时为具体命令名称
\item \texttt{client\_type}：发送者身份标识，取值包括 \texttt{unity}、\texttt{mediapipe}、\texttt{raspberry\_pi}、\texttt{debug} 四种。客户端在注册时通过此字段声明自身类别，服务端据此维护已连接客户端的注册表
\item \texttt{request\_id}：请求追踪标识，采用UUID格式。当命令需要响应时，发起方携带此字段，响应方须原样回传以关联请求—响应对
\item \texttt{relay\_to}：直接转发标识。若消息中包含此字段，服务端不再将消息投入Agent队列，而是直接转发至目标客户端，实现低延迟的客户端间直连通信
\end{itemize}

其中，\texttt{register}类型具有特定的语义约定：该类型仅由客户端向服务端发起。当客户端首次连接到服务端时，须发送一条\texttt{register}类型消息并携带\texttt{client\_type}字段标识自身类别。服务端在收到注册消息后记录该连接的身份信息，后续该连接发送的消息无需重复携带\texttt{client\_type}，服务端将自动补充发送者身份。

JSON文本协议具有三方面优势：文本形式便于开发阶段的调试与日志分析；统一的数据封装方式简化了协议解析逻辑；Base64编码虽然增加了约33\%的数据体积，但换取了协议的一致性与可维护性。考虑到本系统运行于本机与局域网环境下，网络带宽充足且延迟极低（通常低于5ms），上述开销在实际使用中完全可接受。表\ref{tbl:protocol-examples}按消息类型给出了四种典型场景下的协议使用实例。

\subsection{系统控制命令}

基于上述协议格式，系统定义了一套控制命令用于各模块间的协调交互。表\ref{tbl:command-table}按接收客户端分组，汇总了全部控制命令的发起方、接收方与使用说明。

命令的命名遵循三级约定，以前缀区分语义类别：

\begin{enumerate}
\item \textbf{\texttt{request:}前缀}：请求型命令，期望接收方处理后返回响应。发起方须携带\texttt{request\_id}字段，接收方响应时原样回传以关联请求。典型实例为\texttt{request:screenshot}——Agent请求Unity或MediaPipe客户端截取当前画面以查看运行状态。
\item \textbf{\texttt{input:}前缀}：输入注入型命令，用于向目标客户端模拟用户交互事件。典型实例包括\texttt{input:submit}（触发提交事件）、\texttt{input:move}（将食指指向映射为输入坐标）、\texttt{input:cancel}（取消当前输入）和\texttt{input:navigate}（触发导航操作）。
\item \textbf{无前缀}：直接控制命令，即发即忘，无需响应。此类命令主要用于设备控制与状态同步，如灯光模式切换（\texttt{chase}、\texttt{solid}、\texttt{rainbow}、\texttt{breathing}）、音符事件的灯光伴随反馈（\texttt{gain\_note}、\texttt{drop\_note}、\texttt{play\_note}），以及配置开关（\texttt{hand\_direction}）。
\end{enumerate}

\section{智能体EchoAgent实现}

作为为《回声之境》服务的智能体，本文将其命名为 EchoAgent。EchoAgent 内部基于大语言模型构建，作为整个系统的决策层和中枢节点。TCP Socket 服务器与 EchoAgent 之间通过一个异步消息队列进行通信：服务器负责接收来自各类客户端（Unity、MediaPipe、Raspberry Pi 等）的消息，并将它们投入共享的消息队列；EchoAgent 则定时从队列中批量取出消息，经大语言模型理解后，自主决策并调用相应工具完成响应。

在系统启动流程上，本设计先创建全局消息队列，再创建 TCP 服务器并注入该队列的引用，最后创建 EchoAgent 实例，使其同时持有队列与服务器的引用。这种顺序确保了各组件在初始化时能够正确建立关联。

由于智能体需要主动向各个已连接的客户端发送消息或命令，本系统将这类操作封装为可被大语言模型调用的工具（Tools）。这里存在一个设计上的矛盾：工具的参数必须是字符串或数字等简单类型，以便大语言模型生成，然而向客户端发消息这一操作本质上需要持有 TCP 服务器实例的引用。为解决这一矛盾，本系统利用面向对象的闭包特性，在 EchoAgent 初始化时将 TCP 服务器实例保存为其成员属性，而工具函数则作为内部方法定义，通过隐式绑定到 \texttt{self} 来访问服务器实例，从而在不破环工具参数类型约束的前提下实现了对服务器的控制。

整个系统运行时，TCP 服务器与 EchoAgent 各自在独立的无限循环中运作：TCP 服务器持续监听端口、接收并解析来自客户端的消息，同时暴露发送消息的接口供外部调用；EchoAgent 则按固定时间间隔（默认五秒）批量取出消息队列中积压的所有消息，交由大语言模型进行理解与推理，再由模型自主选择并调用合适的工具完成响应。

\subsection{DeepAgent}

本系统采用 \textbf{DeepAgent} 框架，基座模型采用 \textbf{Qwen3.6-Plus}。DeepAgent是一个基于LangGraph和LangChain构建的智能体框架，具备深度的规划能力、高效的上下文管理及灵活的子代理委派机制，可通过\texttt{write\_todos}工具自动拆解复杂任务并动态调整执行计划；自动记忆压缩有效解决超长任务带来的上下文溢出问题；支持通过\texttt{task}工具实时创建子代理，在实现复杂功能的同时保持主代理上下文的简洁高效；无缝对接LangGraph的状态管理与LangSmith的监控、评估与部署能力。

\subsection{技能（SKILL）设计}

在大语言模型智能体的实际部署中，如何让模型有效理解任务环境并执行相应操作，是一个核心问题。传统的方案通常依赖提示词工程（Prompt Engineering），通过自然语言描述向智能体传递系统知识。然而，这种方式存在显著局限：提示词长度受限、描述易产生歧义、模型对结构化信息的理解效率远高于自由文本。

基于上述考量，本系统设计了一套专用的技能，通过结构化的机器可读格式向智能体传递系统知识，使智能体能够准确掌握交互系统的架构细节、通信协议、感知能力与可控设备。

\textbf{（1）系统架构描述模型}

 SKILL体系首先定义了系统的层次化架构模型。本系统采用“感知层—决策层—执行层”的三层星型拓扑结构，其中感知层包含手势识别、面部情绪识别与交互应用状态同步三个独立模块，各模块均以TCP Client方式向决策层上报数据；决策层以Qwen3.6 VLM为基座模型，结合DeepAgent框架实现Tool Calling能力；执行层则由Unity客户端与树莓派物理装置组成。SKILL中通过结构化字段明确各层的职责边界与数据流向，使智能体能够理解其在系统中的定位与作用。

\textbf{（2）标准化通信协议抽象}

智能体与各模块间的通信遵循标准化的JSON-over-TCP协议。SKILL对协议格式进行了形式化描述，包括消息类型体系（text、image、command、register四种消息类型）、客户端身份标识（unity、mediapipe、raspberry\_pi、debug四种）、以及请求追踪机制（request\_id字段用于关联请求与响应）。这种形式化描述使得智能体能够精确理解每条消息的语义，而非依赖自然语言的模糊表述。

\textbf{（3）感知事件模型}

感知层各模块上报的事件是智能体决策的主要输入来源。SKILL定义了一套统一的事件模型：每个事件包含来源标识（source）、事件名称（event）、事件数据（data，含位置坐标、置信度等）以及时间戳（timestamp\_ms）。在此基础上，SKILL进一步描述了各感知模块的具体事件类型与触发条件。

对于手势识别模块，定义了手部出现/消失、捏合（pinch）、捏合释放、双手张开、左右滑动手势等事件，并说明了捏合检测的算法原理——通过计算拇指尖（landmark 4）与食指尖（landmark 8）的欧氏距离实现，阈值设为0.06。对于面部识别模块，则定义了面部出现/消失事件，以鼻尖位置作为参考点。通过这种结构化描述，智能体能够准确判断当前收到的感知数据代表何种交互状态。

\textbf{（4）工具函数接口规范}

Tool Calling是智能体控制外部设备的唯一途径。SKILL定义了六个核心工具函数，每个函数包含功能描述、参数列表与返回值约定。工具函数的设计遵循“单一职责”原则：\texttt{control\_lights}负责灯光控制（颜色、亮度、模式三个参数）；\texttt{send\_to\_client}负责向指定客户端转发消息；\texttt{advance\_application\_chapter}与\texttt{trigger\_application\_event}分别用于交互应用叙事控制；\texttt{play\_music}与\texttt{set\_environment}则分别控制音频与视觉环境。参数类型均采用简单字符串或数值，避免复杂嵌套结构，降低VLM解析出错概率。

\textbf{（5）上下文感知与交互策略}

单纯的实时响应不足以构建连贯的交互体验，智能体还需理解交互应用叙事上下文与用户情感趋势。SKILL定义了上下文记忆的管理规范：智能体应维护最近五轮交互历史、当前交互应用章节与场景信息、参展者已获音符列表、以及情绪变化趋势。这些信息共同构成了决策的上下文基础。

在交互策略层面，SKILL定义了触发—响应的映射规则。当检测到手势捏合时，智能体根据当前场景决定触发音符演奏或场景交互；当情绪检测为正向时，灯光采用暖色调并提升亮度，音乐节奏加快；当情绪检测为负向时，则采用冷色调并降低亮度。这种规则化的策略描述使得智能体的决策行为具有可预测性与可解释性。

\textbf{（6）系统约束边界}

为防止智能体产生异常行为，SKILL还定义了系统级的约束边界，包括实时性要求（手势响应延迟低于100ms、灯光控制延迟低于200ms）、技术部署约束（仅支持局域网环境）以及内容安全限制（四个音符须按序获得、情绪反馈须柔和避免强刺激）。这些约束作为智能体决策的边界条件，确保系统在可控范围内运行。

\section{TCP通信与并发控制实现}

\subsection*{Unity客户端的线程安全发送机制}

Unity引擎基于单线程执行模型，其生命周期方法（如 \texttt{Update}、\texttt{FixedUpdate}等）均在主线程中运行。然而，TCP网络通信涉及I/O操作，为避免阻塞主线程导致帧率下降，本系统在 \texttt{AgentCommunicator} 组件中采用了异步发送机制，并通过信号量（Semaphore）实现线程安全的发送控制。

具体实现上，\texttt{SendRawAsync} 方法采用 \texttt{SemaphoreSlim} 作为发送锁，确保在同一时刻仅有一个发送任务持有网络流的使用权。当多个协程或异步任务同时发起发送请求时，发送锁保证这些请求被串化执行，避免TCP粘包或数据交错问题。锁的获取与释放位于 \texttt{try-finally} 块中，确保即使在网络异常情况下也能正确释放资源，防止死锁发生。

此外，\texttt{AgentCommunicator} 通过 \texttt{SynchronizationContext} 将接收到的网络消息投递回Unity主线程执行回调，从而在不影响应用帧率的前提下完成消息的解析与分发。这种设计在保持网络通信高效性的同时，确保了所有应用逻辑均在主线程中执行，符合Unity的线程安全要求。

着色器（Shader）是运行在 GPU 上可编程的图形程序，分为顶点着色器（Vertex Shader）和片元着色器（Fragment Shader）\citing{feng2016unityshader}。如图~\ref{fig:unity-shader}，GPU 的渲染管线包括下面的工序：顶点着色器处理顶点的坐标转换信息，而片元着色器处理像素颜色数据计算信息。顶点着色程序从GPU 前端模块中获取到图元信息并执行顶点坐标的空间转换、 法向量的空间转换以及光照计算等操作，最终将计算的数据传输到指定的寄存器之中；随后片元着色程序从中提取所需要的数据，通常为纹理、坐标、光照信息等。并根据这些数据以及从应用程序传递而来的纹理信息执行每个片元的颜色计算，最后将处理后的数据信息传送至光栅操作模块。片元着色程序对每个片元进行独立的颜色计算，最终输出的值就是该片元最后呈现的颜色\citing{chen2024u3d}。

在Unity基于URP渲染管线中，可使用Cg或HLSL语言编写着色器，也可使用节点式的可视化编辑工具ShaderGraph。将风速、风强度、噪声纹理缩放、草地区域色彩值等设置为可实时调整的材质属性，以便后续结合多模态情感识别结果进行动态变化。下面以半透明抖动山峦和风格化草地为例说明着色器设置。

\textbf{（1）半透明抖动山峦着色器}

远景山峦在场景中承担着视觉引导与氛围渲染的职责，其半透明且边缘模糊的视觉效果通过菲涅尔效应与顶点随机偏移协同实现。

\textbf{菲涅尔材质}：采用Schlick近似公式计算菲涅尔因子：

$$F_{R} = F_{0} + (1 - F_{0}) \cdot (1 - \cos\theta)^{5}$$

其中 $F_{0}$ 为基础反射率，$\theta$ 为视线方向与表面法线的夹角。当 $\theta$ 增大时，菲涅尔因子趋近于1，使山峦边缘呈现明亮的发光效果；而接近正对视角的区域则保持较高的透明度，呈现出轮廓模糊、若隐若现的质感。该特性使山峦在深色背景下呈现出柔和而富有层次感的轮廓线。

\textbf{顶点着色器随机偏移}：山峦的抖动效果于顶点着色器中实现。通过引入基于时间的连续噪声函数，对各顶点进行随机的微小偏移，形成起伏不定的轮廓形态。

\textbf{Uniform参数控制}：为便于外部动态调控山峦的视觉表现，着色器预留了四个可调参数：

\begin{itemize}
\item \textbf{FresnelPower}（Float）：控制菲涅尔效应的衰减速率，较小取值使边缘发光范围扩展，较大取值则使发光收敛于更窄的边缘区域；
\item \textbf{FresnelColor}（Color）：定义边缘发光的颜色，可根据场景氛围进行调整；
\item \textbf{WobbleSpeed}（Float）：控制抖动动画的时间节奏，较快速度产生轻微颤动，较慢速度则呈现缓慢起伏；
\item \textbf{WobbleIntensity}（Float）：控制抖动的幅度大小，决定山峦轮廓的模糊程度。
\end{itemize}

上述参数通过C\#脚本直接引用材质对象进行动态修改。在Unity中，可通过 \texttt{GetComponent<Renderer>().material} 获取材质实例，并使用 \texttt{material.SetFloat()}、\texttt{material.SetColor()} 等方法实时调整参数值。该方式便于与智能体模块对接，智能体可通过标准化接口向渲染模块下发参数调整指令，实现山峦视觉表现随情绪氛围的动态变化。

\textbf{（2）草地动态效果}

草地场景的动态效果本质上是草丛几何体顶点的规律性偏移，需要在顶点着色器上操作。为模拟随风摆动的动态，最核心的工具是连续噪声函数，其数学目标是构造一个连续可导、局部相关、全局随机的函数 $N(x,y,z) \in [-1,1]$。相比真正的随机数，它满足偏导数 $\partial N / \partial x \neq 0$ 且变化平滑。如图\ref{fig:noise-2d}所示，这是一张满足上述要求的在二维空间上分布的噪声图像，将其灰度值线性映射到 $[-1,1]$ 区间即可表示风力大小。将噪声函数的位移值随时间移动采样，构建滚动纹理，即可作用于草丛的顶点偏移形成摆动效果。

\textbf{（3）性能优化}

草地场景中存在成千上万的渲染实体，如果不加任何优化，将会造成严重的图形 API 调
用开销。针对这个问题，剔除技术和 GPU Instancing 技术是两种有效的优化手段。

在三维图形渲染中，剔除技术是提升性能的重要手段之一。其中，视锥体剔除（Frustum Culling）作为一种基于空间可见性的剔除方法，其核心原理是去除位于摄像机视锥体范围之外的三维模型\citing{chen2024u3d}，从而避免对不可见物体进行后续渲染计算。通过实施视锥体剔除，可显著降低每一帧中需提交至渲染管线的几何体数量。这一方面减少了 CPU 需要处理的顶点数据量，另一方面也直接降低了 GPU 所需执行的顶点着色与片元着色负载，进而有效减轻overdraw 现象。与此同时，由于场景中实际提交渲染的物体数量减少， CPU 生成的 DrawCall数目也相应下降，有助于缓解图形 API 调用开销，提升绘制效率。

此外，为进一步优化渲染性能，还可结合 GPU Instancing 技术。该技术通过合并相同网格的多次绘制调用，能够进一步减少 DrawCall 数量，从而在 CPU 与 GPU 之间实现更高效的任务分工与协作，最终促进整体帧率的提升与渲染流程的稳定。在 Unity 引擎中，可通过打开 Terrian 中的 Draw Instanced 选项、将渲染管线中 GPU Resident Drawer 设置为 Instanced
Drawing 以及开启草丛材质的 Enable GPU Instancing 选项启用该技术。

\subsection{手势和面部动态捕捉}

本系统采用MediaPipe方案进行实时手势关键点检测与面部动态捕捉。MediaPipe作为轻量级、跨平台的解决方案，能够在普通摄像头下实现稳定的实时识别，适合展览场景部署。

\textbf{系统架构}：整个捕捉系统采用事件驱动的模块化架构，主要包含三个核心组件。\textbf{HandDetector}和\textbf{FaceDetector}分别运行在独立的守护线程中，负责从摄像头捕获帧并进行关键点检测；检测器内部维护状态机，仅在检测状态变化时生成事件，避免每帧发送冗余数据。事件通过\textbf{EventBus}（基于Python的queue.Queue实现线程安全队列）发布，形成生产者—消费者模型。\textbf{TcpSender}在后台线程中运行asyncio事件循环，从EventBus消费事件并通过TCP协议发送至智能体服务端。这种解耦设计使得检测器与网络发送逻辑完全独立，异常处理完善，网络错误不影响检测流水线正常运行。

\textbf{手部检测器}：基于MediaPipe HandLandmarker模型，支持21个手部关键点检测。检测器内部维护状态机，状态转换路径为：\texttt{NO\_HAND} $\rightarrow$ \texttt{HAND\_PRESENT} $\rightarrow$ \texttt{PINCH} $\rightarrow$ \texttt{PINCH\_RELEASED} $\rightarrow$ \texttt{NO\_HAND}。支持的手势事件包括：\texttt{hand\_detected}（手部首次出现）、\texttt{hand\_lost}（手部完全消失）、\texttt{pinch}（拇指与食指捏合，触发时附带平均坐标）、\texttt{pinch\_released}（捏合释放）、\texttt{open\_both\_hands}（左右手同时张开）、\texttt{swipe\_left}与\texttt{swipe\_right}（手腕快速左右滑动）。关键算法方面，捏合检测通过计算拇指尖（landmark 4）和食指尖（landmark 8）的欧氏距离实现，阈值设为0.06（归一化坐标）；手部张开检测检查所有指尖（landmark 8, 12, 16, 20）与手腕（landmark 0）的距离；滑动手势则通过跟踪手腕X坐标的速度，超过阈值时触发。

\textbf{面部检测器}：基于MediaPipe FaceLandmarker模型，检测468个面部关键点。检测器以鼻尖位置（landmark 1）作为面部中心参考点，维护简单的布尔状态（\texttt{face\_present}或\texttt{face\_absent}）。支持的事件包括：\texttt{face\_detected}（面部首次出现，附带鼻尖坐标）、\texttt{face\_lost}（面部完全消失）。与手部检测器相同，面部检测器也采用状态机驱动，仅在面部出现/消失状态变化时发布事件，避免每帧发送冗余数据。

\textbf{统一事件格式}：所有检测器共享的\textbf{UnifiedEvent}数据结构包含以下属性：\texttt{source}（事件来源，"hand"或"face"）、\texttt{event}（事件名称）、\texttt{data}（字典类型，包含位置坐标、置信度分数等）、\texttt{timestamp\_ms}（事件时间戳，毫秒级）。事件通过JSON格式序列化后，经TCP协议发送至智能体服务端，协议采用长度前缀（4字节大端序无符号整数）+ UTF-8编码JSON载荷的二进制帧格式。

MediaPipe客户端同样以TCP Client方式连接至智能体服务端，上报识别结果。

\subsection{场景布置}

技能图标使用矢量绘图工具（Affinity）绘制四个音符图案，采用贝塞尔曲线（Bézier Curve）构建流畅的音符轮廓线条。贝塞尔曲线是一种广泛应用于计算机图形学的参数曲线，通过控制点定义曲线形态。本设计使用三次贝塞尔曲线（cubic Bézier），其数学表达式为$B(t) = (1-t)^3P_0 + 3(1-t)^2tP_1 + 3(1-t)t^2P_2 + t^3P_3$，其中$P_0$、$P_1$、$P_2$、$P_3$为控制点，$t \in [0,1]$为参数。通过调整中间控制点$P_1$、$P_2$的位置，可以灵活控制曲线的弯曲方向与曲率，使音符图案呈现出自然、优美的线条形态。矢量绘图完成后，将图案缩放到合适比例打印在A4纸上，粘贴于椴木板，使用美工刀雕刻出镂空图形，最后用装饰性麻绳串联并固定于展台。整体场景布置注重实体装置与虚拟界面的视觉呼应。

\textbf{第三章：深流之径・未被触及的知识海（敬畏→自由）}。本章以知识潮机制为核心，灯光由深蓝缓慢波动向蔚蓝规律波动过渡。在浅滩区，参展者每获取一个知识碎片，水面上涨一分，LED灯阵亮度提升一个等级；集齐六个碎片解锁海浪音符后，灯光切换为稳定蔚蓝。在深潮区化解三道情感浪潮后，风音符解锁，四个音符旋律合为一首完整曲子，灯光进入全彩自由模式，参展者获得完全的表达与探索自由。此时四个音符均可自由演奏，每个音符的奏响都会触发对应的视觉、听觉与灯光联动变化。

整个交互流程约25至35分钟，系统在全程运行中保持了稳定的帧率（60 FPS）与低延迟响应（手势识别到视觉反馈平均延迟低于100ms）。实体装置与虚拟场景的同步效果良好，LED灯阵的色彩、亮度与闪烁模式能够准确反映当前的场景情绪基调与交互状态。

本系统在设计理念和技术实现上与《基于大语言模型的游戏目标导向交互》论文提出的方法存在诸多相似之处，同时也根据展览交互的特点进行了适应性调整。以下从几个维度进行对比分析：

\subsection*{架构设计对比}

论文提出的双LLM架构使用DLM（对话语言模型）和QALM（问答语言模型）分别负责对话生成和状态追踪，实现了生成能力与决策能力的解耦。本系统采用了类似的解耦思想，但实现方式有所不同：

\begin{itemize}
    \item \textbf{论文方法}：严格的双模型架构，DLM专注于自然语言对话生成，QALM专注于状态评估和决策
    \item \textbf{本系统方法}：单VLM（视觉语言模型）结合结构化技能（SKILL）体系，通过Tool Calling机制实现多功能集成
    \item \textbf{优势对比}：论文方法在对话生成质量上有优势，本系统方法在跨模态理解和工具调用灵活性上有优势
\end{itemize}

\subsection*{状态追踪机制对比}

状态追踪是目标导向交互的核心技术，两种方法在状态追踪的实现上各有特点：

\begin{itemize}
    \item \textbf{论文方法}：基于谜题图（Puzzle Graph）的显式状态建模，状态转换通过自然语言问题评估实现
    \item \textbf{本系统方法}：基于情感状态图的隐式状态建模，状态转换通过多模态特征融合和概率计算实现
    \item \textbf{适用场景}：论文方法更适合任务导向的对话交互，本系统方法更适合情感导向的展览体验
\end{itemize}

\subsection*{交互自主性与叙事连贯性平衡}

两种方法都致力于平衡交互自主性与叙事连贯性，但侧重点不同：

\begin{itemize}
    \item \textbf{论文方法}：通过状态图提供结构化框架，在框架内允许自由对话，强调“强自主性”
    \item \textbf{本系统方法}：通过情感状态引导和自适应反馈，在保持情感叙事连贯性的前提下支持个性化探索
    \item \textbf{设计哲学}：论文方法更接近游戏设计中的“涌现式玩法”，本系统方法更接近展览设计中的“情感化体验”

\subsection*{在展览场景中的适用性}

对于实体展览场景，本系统的方法具有更好的适用性：

\begin{enumerate}
    \item \textbf{多模态交互支持}：展览交互需要支持手势、表情等多种输入方式，而不仅仅是文本对话
    \item \textbf{情感体验导向}：展览更注重情感共鸣和沉浸感，而非任务完成度
    \item \textbf{实时性要求}：展览交互需要低延迟的实时反馈，本系统的分层决策机制更适合这一需求
    \item \textbf{物理空间整合}：展览需要虚拟内容与实体装置的协调，本系统的反馈协调机制专门为此设计
\end{enumerate}

\subsection*{相互借鉴与融合可能性}

两种方法各有优势，未来可以相互借鉴和融合：

\begin{itemize}
    \item \textbf{从论文方法借鉴}：引入更精细的状态追踪机制，提升叙事引导的精确性
    \item \textbf{从本系统方法借鉴}：论文方法可以扩展多模态感知能力，支持更丰富的交互形式
    \item \textbf{融合方向}：结合双LLM架构的对话生成优势与本系统的多模态协调能力，构建更强大的交互系统
\end{itemize}

总体而言，本系统在目标导向交互框架的基础上，根据展览交互的特点进行了创新性调整，实现了更适合实体展览场景的沉浸式多模态交互方案。


\chapter{总结与展望}

\section{主要贡献与创新点}

综合上述工作，本系统的主要贡献与创新点可以归纳为以下三个方面：

\begin{enumerate}
\item \textbf{轻量化数据需求}：不同于Lumine等研究需要数千小时的标注交互数据，本系统基于现成VLM的零样本能力，仅需少量场景-决策对应关系即可运行，大幅降低了数据收集与标注成本，使系统在有限资源下仍具备快速部署的能力。
\item \textbf{多模态融合决策}：系统同时整合视觉（手势、面部情绪）、交互应用内部状态以及上下文记忆，通过VLM做出综合决策，而非传统系统的单一模态简单映射。这种融合决策机制使系统能够更准确地理解参展者的整体状态，输出更贴合情境的响应。
  \item \textbf{物理世界交互}：系统不仅控制交互叙事的推进与虚拟场景的视觉变化，还能实时影响展厅内的物理设备（LED灯阵等），通过TCP通信驱动树莓派PWM控制器实现灯光的动态变化，真正实现了虚拟世界与现实空间的无缝融合，使展览交互体验从屏幕内延伸至实体空间。
\end{enumerate}

\section{不足与反思}

尽管本次毕业设计基本完成了预定目标，但在实际开发过程中也暴露出若干不足之处，值得在后续工作中加以改进。

\begin{enumerate}
\item \textbf{交互应用内容深度不足}：由于开发时间与个人精力有限，《回声之境》在叙事内容、关卡设计与情感表达等方面仍有较大的打磨空间。四个音符的象征意义与交互机制的结合尚不够紧密，部分场景的情绪基调与交互反馈之间的关联度可以进一步提升。
\item \textbf{情绪识别精度有限}：当前系统采用现成的MediaPipe方案进行手势与面部关键点检测，情绪状态的量化维度较为单一，尚未充分利用面部关键点的时序变化实现更细腻的情感推断。
\item \textbf{实体装置与虚拟场景的同步精度}：目前灯条控制与交互应用内事件之间存在一定的响应延迟，实体装置的物理反馈与虚拟画面的时间一致性尚有优化空间。如需提升至展览级别的用户体验，需在通信延迟优化与同步策略设计上做更多工作。
\item \textbf{智能体的决策可解释性}：尽管系统集成了Phoenix链路追踪工具，但VLM在Tool Calling决策过程中的推理逻辑仍像一个”黑箱”，难以向非技术用户解释为何在某一时刻选择了特定的工具调用。在面向普通观众的展览场景中，增加决策的可解释性将有助于提升用户对系统的信任感。
\end{enumerate}

本文设计并实现了一套面向实体展览的沉浸式多模态交互系统《回声之境》。系统以Unity引擎为核心交互平台，构建了"感知层—决策层—执行层"的三层星型拓扑架构：感知层整合手势识别、面部情绪识别与交互应用状态同步三源信息，决策层以Qwen3.6 VLM结合DeepAgent框架作为智能决策中枢，执行层驱动虚拟场景的实时渲染与实体LED灯阵的动态响应。在通信层面，设计了标准化的JSON-over-TCP协议，实现了多模块间的松耦合数据交换。在交互设计层面，以旅人的情感成长弧线为叙事主线，通过四个音符的递进解锁构建了从迷茫到自由的情感体验闭环。

本系统的核心创新在于：利用VLM的零样本能力降低了对大规模标注数据的依赖；通过多模态融合决策实现了对参展者整体状态的深度理解；将虚拟场景与物理灯光装置的联动控制真正落地，使展览交互从屏幕延伸至实体空间。

同时，本文也存在若干不足：《回声之境》在叙事内容的丰富度与关卡设计的精细度上仍有提升空间；情绪识别依赖通用方案，在情感细腻度上存在局限；实体装置与虚拟场景的同步精度可进一步优化；智能体决策的可解释性有待增强。展望未来，随着具身智能、空间推理模型以及更丰富的多模态感知技术的发展，面向实体展览的沉浸式交互系统将在情感理解精度、反馈自然度与体验深度上迎来更大的突破，为公共文化空间中的数字化交互提供更广阔的可能性。
